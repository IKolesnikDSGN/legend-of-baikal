# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Проект русскоязычный: комментарии, документация и коммуникация — по-русски.

## Что это

Сайт конкурса «Легенда озера Байкал». Всё держится на одном интерактивном
кей-вижуале: маска-окно в тумане, шесть светлячков-легенд, скролл-сценарий из
трёх фаз. Репозиторий состоит из двух половин, которые связаны ровно одним
файлом:

```
key-visual/     генерация ассетов: Python + numpy/Pillow, опционально ML
  pipeline/     стадии сборки, kv/config.py — все настройки
  raw/          исходники и ответы модели
key-visual.md   ТЗ: сценарий, фазы, требования, открытые вопросы
site/           Astro 5, статическая сборка
```

Пайплайн пишет `site/public/kv/manifest.json`, фронт его читает. Больше между
ними ничего нет, кроме `id` легенды: он одновременно ключ в `LEGENDS` конфига,
имя файла в `src/content/legends/` и имя кадра в `public/kv/legends/`.

Подробности — в [key-visual/pipeline/README.md](key-visual/pipeline/README.md)
(стадии, обоснования) и [site/README.md](site/README.md) (устройство первого
экрана). Здесь только то, чего нет ни там, ни там.

## Команды

```bash
cd site
npm run dev             # http://localhost:4321
npm run build
npm run check           # прогон всех трёх фаз в Chromium, отчёт + shots/
npm run check:legends   # прогон ленты легенд: индексы, наплывы, карточки
npm run check:types     # astro check: то же, чем метит файлы расширение VS Code
```

`check:types` отвечает на вопрос «почему файл подсвечен красным»: тот же
языковой сервер, что у расширения, но в терминале и по всему проекту сразу.
Версия `typescript` в проекте обязана совпадать с той, что зашита в редактор
(сейчас 6.0.3): на 5.9 проверка проходила чисто, а редактор ту же строку метил
ошибкой — в шестой версии у DOM-типов `hidden` уже не булев, а
`boolean | 'until-found'`. Расходятся версии — расходится и приёмка, молча.

`check` и `check:legends` бьют по **уже поднятому** серверу: `check.mjs` — по
4321, `legends.mjs` — по 4322. Пустой `errors` в отчёте означает, что сцена
собралась: шейдер скомпилировался, текстуры доехали, юниформы не разъехались.
Тестов нет и не планировалось — приёмка здесь браузерная и числовая.

Пайплайн запускается **только из своей директории**: путь до фронта
(`--web`, по умолчанию `../../site/public/kv`) относительный, и из другого
места ассеты уедут мимо репозитория.

```bash
cd key-visual/pipeline
../.venv/bin/python build.py dist/master/master-toned.png --only web
```

## Правила, которые нельзя нарушать

**Ручных шагов нет нигде.** Ни Photoshop, ни «доделать пальцами». Всё, что
попадает в `public/kv/`, пишет стадия пайплайна. Появилась потребность в новом
ассете — это новая стадия, а не файл, положенный руками.

**Фронт не знает наизусть ни одного числа пайплайна.** Доли видимого кадра,
границы планов, бюджет хода, радиус размытия, ширины текстур — всё приходит
через `manifest.json`. Продублированная константа разъезжается молча: поменяешь
`VISIBLE_FRAME`, и точки уедут от своих огней без единой ошибки в консоли.

**Система координат одна — UV всего канваса, включая поля.** Пересчёт в экранные
координаты живёт в двух местах и только в них: `Scene.screenOf()` на CPU и
`screenUv()` в шейдере. Через `screenOf` проходят и DOM-кнопки, и светлячки, и
цель дрейфа пятна. Вторая формула для того же места неизбежно разъедется.

**Вертикаль в шейдере растёт вверх.** Текстуры грузятся с `flipY`, а точки,
курсор и DOM живут в координатах от верха. Это уже ломало три вещи разом: маска
шла по Y навстречу мыши, светлячки уезжали от огней, камера двигалась не туда.

**Плашки друг относительно друга не двигаются.** Граница планов идёт по кромке
леса, и по обе стороны от неё лежит одна и та же местность из двух разных
файлов — любой взаимный сдвиг даёт ступеньку поперёк кадра. `PLANE_PARALLAX` в
конфиге остался, но амплитуда нулевая, весь параллакс делает попиксельный изгиб
по глубине.

**Восемь текстурных юнитов — потолок.** WebGL1 гарантирует восемь на
фрагментный шейдер, сцена держит ровно восемь: три плашки, форграунд, карта
данных, шум и два слоя легенд. Поэтому всё лишнее едет каналами: глубина кадра
легенды — в его собственной альфе, контурная калька — в альфе размытой копии,
её расфокусированный уровень — в синем канале карты глубины (R глубина,
G эмиссия, B калька в расфокусе).
Девятая текстура сломает сцену на слабых устройствах, и не в консоли, а чёрным
экраном.

**Форграунд первого экрана — двухцветная калька того же кадра.** Плоский фон
темы `brand` и белые формы: контур ландшафта и белые массы шести объектов-легенд.
Лежит в альфе `plates/fog-*.webp`, приходит из стадии `outline`. Оба цвета сцена
читает из токенов (`--bg`, `--fg-highlights`) — в шейдере их нет числами. Калька
обязана совпадать с мастером пиксель в пиксель: край маски шириной в один-два
пикселя покажет любой сдвиг сдвоенным контуром, поэтому у неё та же выборка, тот
же изгиб по глубине и тот же параллакс, что у резкого кадра.

**Компонент не знает ни одного цвета и ни одного размера в числах.** Всё —
токены из `site/src/styles/tokens/` и классы `u-*` из `utilities.css`, и цвет
берётся с семантического слоя (`--bg`, `--fg`, `--accent`), а не с примитива
(`--coral`, `--dark-blue`). Примитив, вписанный в компонент, не переживёт смену
`data-theme` и не сообщит об этом ошибкой. Нужного отступа нет в шкале — это
правка шкалы, а не класс с пикселями. Устройство и обоснования — в
[site/README.md](site/README.md), витрина всех групп — `/tokens`.

**Дивайдер один на весь сайт.** Линия и её отбивки живут в `site/src/styles/rule.css`
классом `.rule`, и все семь мест — первый экран, карточка легенды, «О территории»
(обе), «О конкурсе», голосование, «О проекте» — берут его. В футере линии нет вовсе:
заказчик её снял, части там разводит пустое место. Отбивки взяты с
первого экрана (`--space-lg` сверху, `--space-xs` снизу), там пара «заголовок → линия →
подписи» и есть эталон. Своё правило в компоненте означает, что «одинаково» продержится
до следующей правки: шесть дивайдеров с личными числами разъезжаются молча. Блоку
остаётся только своя роль — цвет поверх кадра у первого экрана, полоса прогресса у
карточки.

Отбивок под линией две, и вторая тоже живёт один раз: `.rule--loose` — втрое больше
общей (`calc(var(--space-xs) * 3)`, замер 36 px против 12). Стоит по просьбе заказчика
там, где под линией начинается не подпись к заголовку, а самостоятельная часть блока:
«Ключевые объекты», «О конкурсе», «О проекте». Множитель от того же шага шкалы, поэтому
«втрое» остаётся втрое и после правки шкалы.

**Текст на странице набирается по формату.** `text-align: justify` стоит у всех
контентных абзацев: голосование, «О конкурсе», «О территории» (сцена и закрывающая
мысль), карточка легенды, «О проекте». Последняя строка остаётся по левому краю сама —
это дефолт `justify`, и растягивать её не надо.

У центрированных блоков это ещё и условие центровки: при рваном правом крае масса
текста стоит левее центра бокса — замер даёт 21–32 px, и абзац читается сдвинутым, хотя
бокс стоит ровно по центру. `text-wrap: balance` для этого не годится вовсе — он ровняет
длины строк, но бокс остаётся своей ширины, и масса уезжает влево ещё сильнее (замер:
60 px).

**В сцене «О территории» выключку держит `text-align-last`, а не `text-align`.** Строки
там разложены по своим блокам (`hero/lines.ts`), и в каждом блоке строка единственная,
то есть последняя, — а последнюю `justify` не растягивает никогда. Поэтому строки, кроме
последней в абзаце, выключаются `text-align-last: justify`. Переносы от этого не
меняются: разбивка меряет их до выключки, а `justify` правит только пробелы внутри уже
сложенной строки.

**Текстовый стиль назначается целиком**, одним `u-text-style-*`: кегль,
интерлиньяж, трекинг и вертикальный trim приходят вместе. Кегль, поставленный
в одиночку, даёт заголовок с чужой высотой строк.

**В дисплейном заголовке нет места букве «й», и это не придирка.** У стиля
интерлиньяж 0.9 и вертикальный trim по кап-высоте, поэтому краткая не помещается
нигде: в первой строке её срезает верхняя кромка бокса («БАЙКАЛ» выходит
«БАИКАЛ»), во второй она попадает в зону строки выше и читается случайной
пометкой над предыдущим словом. Поэтому в «О конкурсе» стоит «старого порта», а
не «Порта Байкал» — название живёт в первом экране и в «О территории». Тот же
запрет на «ё». Формулировку меняем, а не стиль: интерлиньяж и trim здесь общие
для всех дисплейных заголовков сайта.

Отдельно от системы живёт рампа кей-вижуала (`site/src/styles/kv.css`): это
восемь ступеней из кадра, они меняются только вместе с рендером.

**Репозиторий не под git.** Удаление и перезапись необратимы: смотреть, что
лежит в файле, до того, как его трогать.

## Как устроена сцена

Один фуллскрин-квад рисует всё изображение, второй аддитивный проход — только
светлячки. Заголовки, карточки и кнопки-мишени живут в DOM поверх канваса.
Единственный rAF в `hero/index.ts` крутит всё сразу; общее состояние — в
`hero/state.ts`, его читают шейдер, точки, пятно и скролл.

**Перед сценой стоит экран входа.** Плоский фон темы, крупный леттеринг и две
кнопки — «С аудио» и «Без звука». Звука ещё нет, обе делают одно и то же, выбор
только запоминается (`state.sound`). Под экраном сцена стоит закрытой:
`state.enter` = 0 — форм кальки нет, пятна нет. Вход её запускает, и дальше по
одному ходу: сначала на плоском фоне проступают формы кальки — из прозрачности и
расфокуса, — потом в них открывается окно, потом входят строки первого экрана.
Фон экрана и плоский фон кальки — один и тот же `--bg`, поэтому уход экрана не
подменяет картинку.

**Скролл-сценарий поднимается до входа, а не по клику.** Пин переносит секцию в
свою обёртку, то есть переставляет узлы, а перестановка сбрасывает запущенные
переходы: подними его по клику — и уход экрана входа вместе с ходом строк не
проиграется вовсе. Прокрутку на это время держит `Scroll.stop()` (Lenis), а не
`overflow: hidden`: скрытый скроллбар меняет ширину вьюпорта, и вернуть её можно
только пересчётом границ — тем самым, что переставляет узлы.

**Плавная прокрутка — свойство сайта, а не сцены.** Экземпляр Lenis один на
документ, живёт в `site/src/lib/smooth.ts` и поднимается из `Base.astro`: создай
его в сцене — и на странице без первого экрана инерции не будет вовсе, а два
экземпляра на одном документе дадут два сглаживания одного скролла. Сцена его
подписывает и придерживает на экране входа, но не создаёт и не убивает.

**Три фазы одной маской** (ТЗ 1.5):

| Фаза | Что происходит |
|---|---|
| 1, туман | поверх кадра лежит контурная калька, пятно ходит за курсором, поверх — текст и шесть меток |
| 2, раскрытие | пятно разрастается на экран, включается изгиб по глубине |
| 3, легенды | наплывом той же природы сменяются полноэкранные кадры легенд, за последним тем же наплывом приходит фон страницы |

**Переход рисует скролл.** Наплыв занимает первые `WIPE_SHARE` = 35% слота
легенды, дальше кадр стоит: фронт — функция прокрутки, а не анимация со своим
временем. Своего состояния у перехода поэтому нет вовсе — `advanceLegends()`
каждый кадр выводит и слои, и фронт из `state.legendIndex` и `legendLocal`.
Из этого следует главное свойство: наплыв обратим. Отмотка вверх уводит тот же
фронт обратно вниз, а не запускает встречный переход.

**Слоёв всегда ровно два, и любой может быть мастер-кадром.** Наплывает
легенда слота, под ней лежит предыдущая; −1 — мастер-кадр, и он возвращается
из-под первой легенды тем же движением, каким она пришла. Всё, что глубже двух
слоёв, накрыто целиком.

**Нижний слой уходит в тень, пока идёт наплыв** (`LEGEND_DIM`). Два одинаково
ярких изображения в один момент спорят за внимание, и фронт читается швом между
ними, а не проступающей картинкой. Гаснет по корню от фронта: на прямой
уходящий кадр держал полную яркость ровно там, где на него ещё смотрят. Мастер —
такой же нижний слой, поэтому под первой легендой он гаснет тем же кодом.

**Финальный наплыв открывает страницу, а не заливает экран.** За последней
легендой тот же фронт снимает канвас в прозрачность (`alpha: true`, шейдер отдаёт
`1.0 - outro`), и в дыру видно настоящую секцию «О территории» — она весь
финальный слот поднимается снизу обычным скроллом. Своего цвета у финала нет
вовсе: фон и текст приносит DOM. Форма фронта общая — `dissolveWipe` берёт
прогресс и зерно аргументами, зерно у финала своё. Уходящая легенда гаснет под
ним тем же `LEGEND_DIM`.

**Перекрытие держит три числа связанными, и развязывать их нельзя.** Секция под
сценой поднята на высоту сцены (`margin-block-start: calc(var(--hero-h) * -1)`,
атрибут `data-hero-overlap` ставит `hero/scroll.ts` и только в режиме WebGL), и
эта высота обязана равняться длине финального слота: пин отпускает через
`screens` экранов, и секция встанет по верхней кромке ровно тогда, когда поднята
ровно на свой экран. Дай финалу полтора экрана или поменяй высоту первого — пин
отпустит скачком, и на скриншоте это неотличимо. Число живёт один раз: `--hero-h`
в `Hero.astro`, `OUTRO_SCREENS` = 1 в `hero/scroll.ts`.

Оттуда же ещё два условия. **Фона под канвасом нет** — ни на секции сцены, ни на
её слое: он приходит от `data-theme="brand"` и именно он перекрывал страницу под
дырой, поэтому снимается тем же атрибутом. **Порядок слоёв задан явно** — `.hero`
`z-index: 1`, секция под сценой `position: relative; z-index: 0`: она стоит в
разметке позже и позиционированная без своего слоя легла бы поверх канваса,
накрыв кадр вместо того, чтобы открыться из-под него. Поле над кромкой секции
рисует `::before` той же высоты: острова фронта уходят выше того места, куда
секция доехала, и без поля в них просвечивал бы тёмный фон страницы.

**Прокрутка на финале не прерывается.** Кадр последней легенды уезжает вверх
(`OUTRO_LIFT`, потолок задан запасом текстуры под `LEGEND_INSET`), карточка
уходит туда же и гаснет — это продолжение скролла, а не смена состояния. Наплыв
занимает финальный слот целиком, без `WIPE_SHARE`: стоять после него нечему.

`state.outroRise` — докуда снизу канвас снят гарантированно, в худшем случае
разброса `TEAR`. Своего текста финал не несёт, и число осталось замером:
`check:legends` печатает его вместе с фронтом и с `terr` — верхней кромкой секции,
которая к концу пина обязана встать на ноль.

**Маска — порог по двумерному полю, а не растушёванный край.** И у пятна в
тумане, и у наплыва легенд. Форму пятна ломает искажение самой системы
координат (`uWarp`), и только потом меряется расстояние до центра: шум,
добавленный к готовому расстоянию, оставляет круг кругом с бахромой. У наплыва
порог по полю рассыпает фронт на языки и отдельные острова, проступающие выше
основной массы. Все края чёткие — переход в один-два пикселя.

**Форма маски описана ровно один раз** — `MASK_GLSL` в `hero/shaders.ts`. Её
считают два шейдера: сцена и снимок маски для тёмной копии текста
(`hero/textmask.ts`). Вторая формула для той же дыры разъедется в первый же
день, и текст начнёт перекрашиваться не там, где открылся кадр.

**Текста на первом экране два слоя.** Верхний набран вывороткой, нижний —
цветом фона, и открывает его та же маска, снятая картинкой в `mask-image`. Под
дырой светлое небо кадра, и выворотка на нём пропадает. Копия делается
`cloneNode`, а не второй веткой разметки: две версии одного текста в шаблоне
разъедутся на первой же правке.

**У маски своё время.** `state.maskTime` бежит быстрее, пока ведут курсор.
Множитель на общее время вместо этого рвал бы фазу шума при каждом изменении
скорости, и обрывки дёргались бы скачком.

## Настроенные числа

полная, а сверху ещё 20% приходятся на паузу и вход первой легенды. Наплыв
обязан начаться, пока мастер-кадр ещё движется.

## Отладка

В dev-сборке доступен `window.__hero` — `{ scene, blob, state }`. Через него
снимаются все замеры: юниформы шейдера, вычисленные экранные позиции точек,
прогресс фаз. Скриншот сцены + сравнение чисел из `__hero` — единственный
работающий способ проверить, что маска, точки и камера согласованы; на глаз по
скриншоту эти три системы координат неотличимы.

Одноразовые playwright-скрипты для замеров писать в `site/scripts/_*.mjs` и
удалять после. Постоянные — `check.mjs` и `legends.mjs`.

## Текущее состояние

Готово: пайплайн со всеми стадиями, экран входа, первый экран целиком (три фазы,
фолбэки, доступность), шесть текстов карточек, лента легенд с наплывом в обе стороны,
свет от точки при наведении, счётчик собранных легенд, дизайн-система на
токенах, вся страница по pagemap — от первого экрана до футера.

**Все компоненты страницы на токенах.** Текстовый список легенд
(`LegendList.astro`) удалён заказчиком: он был единственным блоком со своими
`clamp` и цветами рампы KV. Следствие, о котором стоит знать: полного текста
легенд без JS и при `prefers-reduced-motion` на странице больше нет — карточки
живут только в скролл-сценарии.

**Страница под сценой** собрана целиком по [pagemap](key-visual/pagemap.pdf):
«О территории» → «О конкурсе» → «Голосование» → «О проекте и организаторах» →
футер. Нет только кнопки регулировки звука — вместе со звуком.

**Темы:** территория `light`, конкурс `brand`, голосование `light`, «О проекте»
`light`, футер `brand`. Территория идёт первой не для ритма: финальный наплыв сцены
открывает её саму — секция поднимается снизу под маской и стоит на месте к тому
моменту, как пин отпускает. Чередование через одну кончается на «О проекте»: тема
там светлая по просьбе заказчика, и два светлых блока подряд — следствие этого
решения. Ритм возвращает футер: он тёмный, и границу между ним и светлым блоком
рисует сам цвет, а не линия. «О проекте» обратно в `brand` не отдавать.

**«О проекте» устроен описью, а не плашками.** Дисплейный заголовок в две строки по
центру, под ним дивайдер, дальше шапка в две равные колонки: справа оба абзаца друг
под другом одним цветом, слева в оставшемся месте кадр в треть колонки. Абзацы не
разведены ни цветом, ни кеглем — это две части одной мысли, и приглушённый второй
читался бы сноской. Ниже четыре строки групп: дивайдер во всю колонку, слева название
с описанием роли, справа логотипы. Своей линии под шапкой нет — её отбивает первая
линия группы.

Линии групп на ступень тише основной, и ступень выбрана замером: на `--muted` (0.64)
линия в один пиксель от `--border` на глаз не отличается вовсе, поэтому стоит
`--muted-secondary` (0.4). Приглушение, которое видно в тексте, в линии не читается —
это общее правило, а не особенность блока.

**Логотипов нет ни одного, и слоты под них свёрстаны пустыми.** У каждой из четырёх
групп в `Project.astro` лежит `items: []` и число ожидаемых мест; пришёл файл — слот
становится `<img>`, пока не пришёл — рамка пунктиром с подписью. Пунктир читается
ожидающим местом, а не элементом дизайна. Придумать логотипы нельзя: это чужие
товарные знаки. Описание группы (`note`) — роль, а не факт: ни имён, ни чисел, ни
сроков, потому что всё это приходит вместе с логотипами.

**Футер лежит на странице, а не в `Base.astro`** — внутренних страниц ещё нет. Его
ссылки уже написаны абсолютными (`/#territory`), поэтому переезд в лейаут будет
одной строкой. Год в копирайте берётся на сборке: вписанное число разъедется молча.

**У голосования свёрстаны все три состояния сразу**, и они лежат в DOM
одновременно: показана одна панель, остальные под `hidden`. Чем состояние
переключается в продакшне — дата, флаг в контенте или админка — ещё не решено,
поэтому у самой левой кромки блока (8 px, `--space-2xs`) по центру по вертикали
стоит иконка-шестерёнка, а
переключатель лежит в поп-апе под ней: он служебный и уйдёт вместе с решением,
поэтому в композиции его быть не должно вовсе (строкой над блоком он читался
частью вёрстки — заказчик на это и указал). Выбор пишется в адрес
(`?voting=during`), чтобы ссылкой на состояние можно было поделиться; без JS ни
иконки, ни поп-апа нет, видна панель по умолчанию. На узком экране иконка уходит в
поток над блоком — у кромки она налезает на текст.

**По умолчанию показано `during`** — состояние с отсчётом до закрытия, коллажем и
кнопкой на проекты: приёмка идёт по нему, и открывать блок пустым «до старта»
незачем. Придёт механизм назначения состояния — `DEFAULT_STATE` уйдёт вместе с
переключателем.

**Подписи «дни / часы / минуты» стоят над числами**, а не под ними: подпись читается
раньше числа, и низ отсчёта остаётся свободным под боковые кадры коллажа — они заходят
на цифры снизу, и под ними подписи пропадали (видна оставалась одна «часы»). Строка
задана явно и подписям, и числам: автоматическое размещение расставило бы подписи над
числом, над двоеточием и над следующим числом.

Набраны они строчными и основным цветом (`u-text-style-text-sm`, `--fg`), а не капителью
надзаголовка — по просьбе заказчика. Тем же стилем набрана строка под отсчётом, по
центру блока: она говорит, что он считает, и текст у неё свой в каждом состоянии — «до
старта голосования» и «до конца голосования». Одна строка на оба состояния была бы
неправдой в одном из них.

**Порядок в панели:** заголовок (уровень h5, в две строки переносом в разметке, по
центру), дивайдер, отсчёт во всю ширину и под ним пояснение — колонкой по центру блока с
левой выключкой и мерой в `ch` на самих абзацах. Заголовок мелкий намеренно: главный
объект блока — отсчёт, и крупный заголовок спорил бы с ним за внимание. По центру он
стоит по просьбе заказчика, и вся ось блока встаёт в одну линию: заголовок, подписи
отсчёта, строка под ним и колонка текста (замер: центр краски 720 при центре блока 720). Служебной строки под
отсчётом больше нет — заказчик её снял.

**Вокруг отсчёта `during` стоит коллаж из трёх кадров, и держит его одна сетка.**
Дорожки те же, что у «О конкурсе»: `minmax(0, 1fr) auto minmax(0, 1fr)`, меру
средней держат сами абзацы. Набор лежит во всех трёх дорожках, боковые кадры — в
крайних и в тех же строках, поэтому они его и перекрывают: абсолютов здесь нет
вовсе, место кадра — это остаток от меры текста. Порядок наложения задан явно
(`isolation` на сетке, `z-index` у кадров): набор набирается скриптом и в потоке
идёт позже, то есть по умолчанию лёг бы поверх.

**Едет сама обёртка, а не картинка внутри неё.** Боковым кадрам внутренний параллакс
`.photo` снят (`animation: none`, `scale: 1`): обёртка идёт вверх, картинка в ней вниз
— два хода в одном месте гасят друг друга, и на глаз стоит либо то, либо другое. Ход
9svh, то есть 162 px пути на экране 900 и 234 px на 1300.

**Кадры стоят в строке текста, а не набора**, и кромка их дорожки совпадает с нижней
кромкой отсчёта на любой ширине. В строке набора цифры на широком экране уходили под
них целиком: отсчёт растёт вместе с блоком, а кадр шириной 18rem — нет. Шире 18rem его
делать тоже нельзя: во всю дорожку он накрывает крайний разряд целиком, а перекрытие
обязано читаться наложением, а не заслонкой.

**Параллакс — в разные стороны одной анимацией**, развёрнутой `animation-direction`:
левый кадр идёт вверх, правый вниз. Второй набор кейфреймов разъехался бы с первым на
первой же правке амплитуды.

**Смещения у двух кадров закреплены по-разному, и это не небрежность.** У левого
закреплена середина пути (`--y` числом): требование мягкое — он должен немного
заходить на цифры, и замер даёт 0–40 px перекрытия, пока отсчёт в кадре. У правого
закреплена верхняя точка — в `--y` прибавлен сам ход, поэтому `--y − --drift` от
амплитуды не зависит вовсе. Требование там жёсткое, не коснуться отсчёта нигде, а ход
задан в `svh` и на высоком экране растёт: с закреплённой серединой замер давал зазор
5 px на 900 и −31 px на 1300, с закреплённой верхней точкой — 35 px на всех высотах.

Широкий кадр под текстом стоит в той же средней дорожке — этим он и равен тексту по
ширине на любом экране (замер: 594/594 на 1024, 390/390 на 480), а под ним по центру
кнопка. Поэтому на узком экране сетка не складывается в одну колонку: уходят только
боковые кадры (`display: none`), пустые дорожки схлопываются сами. Сложи её в одну
колонку — широкий кадр растянулся бы во всю страницу и перестал бы совпадать с
набором.

**Отсчёт стоит в двух состояниях из трёх** и набран во всю ширину блока: до старта
считает по `STARTS_AT`, во время голосования — по `ENDS_AT` (оба в шапке
`Voting.astro`). Формат обязателен со смещением (`+08:00`, Иркутск): иначе браузер
посетителя прочитает дату в своём поясе и покажет чужой отсчёт. Пустая строка вместо
даты по-прежнему работает — отсчёт встаёт с прочерками и просит дату.

**ВРЕМЕННО: даты условные**, чтобы отсчёт было видно живым. Настоящие приходят из
положения о конкурсе — просто поставить их на место условных.

Кегль отсчёта — `cqw` от ширины блока, а не `vw`: за потолком колонки (`--page-max`)
он перестаёт расти вместе с ней, на `vw` продолжал бы и вылез бы за колонку. И
считается от числа знаков (`--chars` ставит скрипт), а не задан числом: дальше 99
дней разрядов семь, и фиксированный кегль вылез бы за дорожку. Делитель замерен —
табличная цифра занимает 0.6 кегля плюс 0.01 на мелкие двоеточия.

**Двоеточия — мелкие спаны в фиксированных позициях.** Дорожки под числа равные
(`1fr`), под двоеточия — по контенту, поэтому разделители стоят на границах третей и
не ездят вслед за шириной цифр. Цвет у них основной: приглушённый знак такого кегля
между тремя огромными числами теряется. Числа при этом разнесены по кромкам блока —
от плотного трекинга (−0.11em, замер: 9 px между краской цифр) каждое стало уже своей
дорожки, и центрированные они отошли бы от краёв. Плотный трекинг при этом тянет за
собой два условия, и оба уже ломали вид: припуск справа у окна знака с обратным полем
(ячейка становится уже краски, и `overflow: clip` срезал цифре правый край) и возврат
трекинга полем в конце числа (трекинг сидит и после последнего знака, поэтому краска
стояла правее центра дорожки на его половину — 20 px). Оба держатся одного `--tracking`. На кегле чисел двоеточие занимало бы место третьего
разряда, а по базовой линии мелкий знак под трёхсотпиксельной цифрой читался бы
провалившимся — отсюда мелкий кегль и выравнивание по центру числа.

**Вход отсчёта — набор по скролл-триггеру:** у каждого знака своя лента из цифр с
целевой в конце, и лента уезжает по Y в своей маске; задержка идёт от старта по
знакам, поэтому число собирается слева направо.

**Шаг ленты — в `em`, а не в процентах.** Процент у `translateY` считается от высоты
самой ленты, а она длиной в несколько знаков: `-800%` уводило её на двадцать пять
тысяч пикселей, и в окне знака оставалась пустота — отсчёта не было видно вовсе, а
цифры успевали улететь за доли секунды. Знак ростом ровно в `1em`, поэтому `em` тут и
есть номер знака. Скорость набора — отношение длины ленты к её ходу; хочешь быстрее,
укорачивай ленту, а не режь ход. Едет позиция ленты, а не подменяется
текст в кадре: подмена шагами читалась мерцанием, а один `transform` с задержкой
считает компоузитор — своих кадров у набора нет вовсе. Команду («отсчёт вошёл в
кадр») приносит `IntersectionObserver` и на этом снимается; своего слушателя скролла
нет — рядом с Lenis он был бы вторым и на каждый кадр. Играет набор **один раз за
загрузку**: отсчёт — показание, а не событие, и пересобирать его при каждом проходе
мимо блока значит объявлять изменение, которого не было. Смена минуты его тоже не
проигрывает. Лента стоит на целевой цифре и без
скрипта, поэтому при `prefers-reduced-motion` отсчёт просто виден числом.

**Между отмоткой ленты и её отпусканием стоит принудительный пересчёт** (`void
el.offsetHeight`), и убирать его нельзя. Набор — это два присваивания подряд:
сначала лента возвращается к началу без перехода, потом отпускается к целевой
цифре. Без чтения геометрии браузер склеивает их в одно, начальным состоянием
перехода остаётся целевая цифра, и движения нет вовсе — молча, без единой ошибки в
консоли. Кадр (`requestAnimationFrame`) на это не годится: он рассчитывает, что
между записями будет отрисовка, а наблюдатель отдаёт первую запись не внутри кадра.
Замер: с кадром лента давала одно положение за проход, с пересчётом — 33.

**Стили для узлов, созданных скриптом, обязаны быть в `:global`.** Скоуп Astro метит
только узлы шаблона, поэтому правило `.timer__reel { display: block }` до ленты не
доходило вовсе — спаны оставались `display: inline`, а к инлайну `transform` не
применяется, и анимация стояла молча, без единой ошибки в консоли. Пишется как
`.timer__num :global(.timer__reel)`: снаружи узел шаблона, и скоуп не потерян.

**Идиома блока одна на всю страницу**, и заводить второй раскладке незачем:
заголовок по центру, дивайдер во всю колонку и короткие пункты в строку под ним.
То же, что у `h1` с `hero__notes` на первом экране. Панели внутри блоков —
бумажные, без скругления, как карточка легенды.

**Исключение из идиомы одно — «О конкурсе», и второго быть не должно.** Блок
ростом в экран (`min-block-size: 100svh`, поля спейсеров внутри этой высоты):
дисплейный заголовок по центру в две строки, дивайдер во всю ширину, под ним три
дорожки — условия слева, абзацы строго по центру блока, кнопки в строку справа.
Оправдано главным CTA страницы; два исключения из четырёх секций — это уже
отсутствие идиомы, а не идиома с исключением.

Три условия этой раскладки. **Ширина — вся страница за вычетом полей, без
`u-container`:** потолок `--page-max` обрезал бы дисплейный заголовок на широких
экранах, а поля те же `--margin`, поэтому по краю страницы блок стоит вровень с
соседями. **Отбивки дивайдера — общие для всего сайта** (`.rule`), и гэпа у обёртки
нет вовсе: пара чисел живёт один раз. Остаток высоты уходит вниз — растянуть композицию
по экрану значило бы развести шапку с содержимым на разное расстояние от линии. **Центр держат равные боковые дорожки** — `minmax(0, 1fr) auto
minmax(0, 1fr)`, и именно `minmax(0, …)`: у `1fr` минимум равен min-content, и
длинное название условия или широкая кнопка растянули бы свою дорожку, сдвинув
центр молча и ровно на разницу. Средняя дорожка `auto`, меру держат сами абзацы
(`ch` на них): вписанная в дорожку мера считалась бы по кеглю секции, а он крупнее
абзаца.

Перенос заголовка стоит в разметке: две строки — композиция блока, а `text-wrap`
делит строку по-своему на каждой ширине.

**На фоне блока — ландшафтный паттерн на канвасе** (`site/src/lib/topo.ts`):
изолинии одного поля высот с тремя вершинами, при прокрутке каждый уровень уезжает
вверх со своей задержкой. Канвас, а не картинка и не SVG: линии двигаются друг
относительно друга, то есть форма пересчитывается каждый кадр. Правила те же, что
у сцены: цвет линии — токен (`--muted-tertiary`, снят с самого канваса), рисунок
детерминирован сеяным генератором (случайный при каждом заходе фон нельзя сверить
скриншотом), своего слушателя скролла нет — прогресс снимается в кадре rAF, а сам
цикл включает и гасит `IntersectionObserver`.

Три вещи в нём связаны, и развязывать их нельзя. **Профиль вершины — конус:** при
нём изолинии равномерны по радиусу и за подошвой поле ровно нулевое, поэтому
фундамент чист сам, без порогов; у гаусса и обратного квадрата линии сбивались в
пучки на склоне и в клубок у вершины. **Радиусы перекрываются** — этим горы и
перетекают друг в друга: сумма конусов держит общий уровень, и низкая линия обходит
две горы одной кривой. **Нижний уровень не нулевой** — линиями рисуются только
склоны, фундамент остаётся пустым; опустишь его к нулю, и канвас затянет линиями по
всей площади. И запас у сетки поля — **вниз**, а не вверх: уровень рисуется
сдвинутым вверх, поэтому нижней кромке экрана соответствует строка поля ниже неё, и
запас вверх оставлял внизу блока полосу без линий.

Условия набраны стилем абзаца, а не надзаголовком с уровнем: подпись приглушённая,
значение основным цветом полужирным. Разный кегль читался бы вторым уровнем текста,
а это одна плоскость с абзацем справа — просто короткими парами.

**Надзаголовков над заголовками секций нет ни в одном блоке** — заказчик их снял,
и возвращать по одному нельзя: строка над `h2` в одной секции из четырёх читается
не акцентом, а сбоем ритма. Каждый блок начинается заголовком, отступ сверху даёт
спейсер секции. Стиль `u-text-style-eyebrow-*` при этом остался и работает —
им набраны подписи полей: единицы счётчика, подписи групп логотипов и колонок
футера. Это ярлыки внутри блока, а не надзаголовки.

**Незаполненные значения показаны, а не выдуманы.** Два условия из четырёх в
«О конкурсе» — сроки приёма и число финалистов — стоят как «уточняется» и набраны
тише подписи (`--muted-secondary`, без веса), тогда как настоящие значения идут
основным цветом полужирным. Вес читается утверждением, и «до 15 сентября» из головы
пережило бы вёрстку. Та же договорённость у даты голосования и у контактов в футере.

Кнопки блока и кнопка заявки в хедере ведут на `/competition` и `/apply` — страниц
нет, тот же статус, что у «Подробнее» в карточке легенды. Висячего якоря `#apply`
больше нет.

**ВРЕМЕННО: на местах будущей съёмки стоят фотографии-заглушки, а не рендеры
легенд.** Всё, что ниже сказано про рендеры в контентных блоках, описывает
состояние с `PHOTOS = false` в [site/src/lib/photos.ts](site/src/lib/photos.ts) —
там же соответствие «место на странице → файл», и оно живёт один раз. Сами файлы
пишет `site/scripts/placeholders.mjs` (17 ландшафтных кадров с Lorem Picsum в
`public/placeholder/`): руками в проект не кладётся ничего и здесь тоже. Придёт
съёмка — скрипт, модуль и папка удаляются целиком.

**Кадр в боксе едет параллаксом за прокруткой** — `site/src/styles/photos.css`,
класс `.photo` на боксе. Прогресс считает браузер по `view()`-таймлайну,
диапазон `cover`: своего слушателя скролла нет, рядом с Lenis он был бы вторым и
на каждый кадр. Ход рисуют `scale` 1.3 с `translate` ±11.5%, и эти два числа
связаны — `translate` применяется до `scale`, поэтому фактический сдвиг равен их
произведению и обязан укладываться в запас `(zoom − 1) / 2`; больше — из-под
кадра покажется край бокса.

Отсюда два условия, которые уже ломали вёрстку. **Картинка в боксе лежит
абсолютом**: в потоке она отдаёт боксу свои интринсик-размеры, и бокс панорамы
уезжал за колонку страницы на 170 px через min-content дорожки грида, а
портретный кадр терял 40 px высоты ряда — молча, без переполнения на самой
картинке. **Пропорция стоит на боксе, а у закрывающего кадра — на его ячейке**:
ячейка и есть элемент сетки, и это её высота задаёт высоту ряда, иначе низ двух
колонок разъезжается на длину левой. Параллакса нет только у коллажа сцены «О
территории»: стенд залипает по центру экрана, и `view()` на залипшем элементе
почти не двигается — своё движение у плашек уже есть.

**Место под видео в блоке — бокс 16:9**, и это число живёт в стилях компонента,
а не приезжает манифестом: 16:9 — формат съёмки, которой ещё нет, а доли кропов
пайплайна к ней отношения не имеют. Внутри стоит заглушка — `fullbleed`-кроп
1.6:1 из пайплайна, — и ложится в бокс обрезкой (`object-fit: cover`), теряя по
краю сверху и снизу. Арт-дирекшна больше нет: `letterbox` 2.8:1 в этом боксе
срезало бы треть ширины кадра. Из манифеста читаются только ширины — набор
реально собранных файлов. Форма держится в CSS, а не атрибутами `width`/`height`:
атрибуты описывают файл внутри, а бокс обязан стоять 16:9 и до загрузки, и после
подмены заглушки на съёмку.

**Кадр раскрывается прокруткой, а подпись на нём — стики.** Клип идёт от
`inset(25%)` со всех сторон до нуля и доходит до полного ровно тогда, когда
верхняя кромка кадра встаёт под верхнюю кромку экрана; начало не из нуля намеренно
— иначе это читалось бы появлением картинки, а не раскрытием стоящей на месте.
Прогресс считает браузер по `view()`-таймлайну, диапазон назван кромками
(`entry 0%` → `exit 0%`), своих чисел у него нет. Ход лежит внутри
`@supports (animation-timeline: view())`, а базовое состояние — открытый кадр: без
таймлайна та же анимация проиграла бы по обычному времени и оставила кадр
подрезанным насовсем.

Подпись — оверлей в той же ячейке сетки, что кадр: разнесена по краям (слева что
это, справа статус заглушки), набрана вывороткой `u-text-highlights` и уходит под
ту же маску, что и кадр, — поэтому клип лежит на всём боксе, а не на одной
картинке. Стики считает по своей ячейке, то есть по кадру: держится середины
экрана, пока кадр идёт мимо, и отпускается на его нижней кромке. Центрируется
сдвигом на половину себя, а не вычетом строки из `50svh`: на узком экране строк у
правой части больше одной. `align-self: start` обязателен — растянутая по ячейке
подпись заняла бы её целиком, и стики двигать было бы нечего.

Цифр в тексте блока нет намеренно, по той же причине, что в карточке `factory`:
фактология территории приходит от заказчика, а подставленное «примерно столько»
переживёт вёрстку.

**Два текста блока разведены сценой в три экрана** (`TerritoryStory.astro`, стоит
на месте прежних двух колонок). Стенд в один экран залипает `sticky`, композиция
одна и та же: заголовок по центру, текст прямо под ним — блок по центру, выключка
левая, — а вокруг шесть кадров в хаотичном порядке. На середине пина один подблок
сменяется другим: строки первого уходят под верхнюю кромку своих масок, строки
второго приходят из-под нижних, уходящие кадры гаснут очередью, приходящие
раскрываются клипом из своего центра.

**Смена идёт своим временем, а не долей прокрутки** — и это единственное место на
сайте, где ход не функция скролла. Прокрутка даёт одну команду: середина сцены
прошла середину экрана. Дальше 0.9 с на `--ease-expo` со шагом очереди по строке.
Команду приносит `IntersectionObserver` на второй половине сцены при корне,
сжатом полями до линии по центру экрана; своего слушателя скролла у сцены нет —
рядом с Lenis он был бы вторым и на каждый кадр. Метка обязана быть высотой в
половину сцены: 1px-метку быстрый скролл проскакивает между кадрами, и команда не
приходит вовсе. Фаза выводится из положения метки, а не переключается по событию,
поэтому прыжок через всю сцену (якорь, восстановление позиции) не ломает
состояние. Сравнивается положение **с линией триггера, а не с верхом экрана**:
иначе на выходе из сцены вниз метка уже выше линии, но ещё ниже кромки экрана, и
подблоки уезжают обратно в первый прямо под уходящей сценой. Линию отдаёт сам
наблюдатель (`rootBounds`), поэтому её половина живёт один раз — в `rootMargin`.

**Подписка наблюдателя живёт в раскладке, а не рядом с его объявлением, и это
условие, а не порядок ради порядка.** У метки нет бокса, пока стенд не поднят
(`.story__mid` до этого `display: none`), а наблюдатель отдаёт первый вызов сразу
после `observe` — на скрытой метке он приходит с прямоугольником из одних нулей,
и `0` от линии по центру экрана всегда «выше»: фаза защёлкивалась в `2` на самой
загрузке, когда до сцены ещё десять экранов пина. Исправиться ей было нечем —
наблюдателя зовут на смену пересечения, а метка шла из «не пересекает» в «не
пересекает». Смены подблоков не было вовсе: сцена приезжала уже переключённой, и
первый текст не показывался ни разу. Ловилось это гонкой со шрифтом
(`document.fonts.ready` ставит раскладку), поэтому и выглядело как «работает
только после хард релоада»: на прогретом кэше раскладка успевала до первого
вызова, на холодном — нет. Замер на холодной загрузке: 200 мс, `scrollY` 0,
высота метки 0, фаза 2. Отсюда же гард в самом наблюдателе — стенд теряется на
ресайзе в низкий экран, и снятая подписка гонится с уже назначенным вызовом: у
метки без бокса положения нет, и трогать фазу нельзя.

Ход ведут `transition`, а не `keyframes`: команда приходит один раз, а
развернуться она обязана из любой точки — отмотка на полпути ведёт строку назад с
того места, где её застали. Из этого же следует, где живёт задержка приходящего
подблока: **на состоянии, а не на элементе.** Приходит на обратном ходу уже
первый подблок, и задержка, приписанная второму навсегда, дала бы на отмотке ту
самую кашу, от которой она поставлена. Сама задержка обязательна: маски у
подблоков свои и стоят почти на одной высоте, и пущенные в один кадр они дают
полсекунды двойного текста.

Строк на строку два узла, и это не запас: `.line` держит `overflow`, `.line__in`
уезжает — один элемент не может разом обрезать себя и уезжать из себя. Разбивку
делает `hero/lines.ts` измерением, и он же ставит `--i`. Маске нужен припуск по
вертикали (`padding-block` с обратным `margin`): у дисплейного заголовка
интерлиньяж 0.9, то есть строчный бокс мельче самих букв, и без припуска маска
срезает ноги «Д» и «Ц».

Порядок в скрипте один и обратный ему не работает: атрибут `data-story-split`
ставится **до** разбивки. Строки считаются измерением, и мерить их нужно в той
раскладке, в которой они встанут, — в потоке подблок шире, и переносы посчитались
бы по чужой ширине. Сам атрибут — ещё и гард: без строк у второго подблока нет ни
одного элемента, которому можно спрятаться, и два текста легли бы друг на друга.
Поэтому раскладка стенда включается тем же движением, что и механика.

Прокрутка в сцене считает ровно одно — смещение композиции вверх за пин
(`--drift`, ±25svh, а на узком экране ±8svh, `view()`-таймлайн, диапазон
`contain` совпадает с залипанием стенда ровно). Только он и стоит под
`@supports`: без таймлайна сцена работает, просто стоит на месте.

Кадров вокруг шесть, по три на подблок, и это **рендеры легенд из пайплайна**, а
не фотографии территории — их в проекте нет ни одной. Взяты они потому, что
разные: один кадр в шести плашках прочитался бы техническим швом, а не сменой
кадров. `alt` пустой намеренно — описать заглушку как берег значило бы соврать в
самом доступном слое. Геометрия коллажа (доли стенда, пропорция, точка кропа)
живёт в компоненте числами: это art-direction, то же исключение, что у слота
логотипа. Геометрий этих две — по краям на широком экране и кластером над
заголовком на ≤900; устройство и замеры второй — в разделе про адаптив ниже.

Базовое состояние сцены — оба подблока стопкой в потоке, как две колонки до этой
правки. Так блок читается при `prefers-reduced-motion` и до разбивки строк.

**Ключевых объектов пять, и показан всегда один.** Заголовок здесь метка над
дивайдером — мелкий кегль по левому краю, — а не крупный по центру: блок открывает
список названий, а не строка над ним. Расстояния над линией вдвое меньше, чем под ней
(`--space-lg` / `--space-2xl`), — линия читается кромкой блока названий, а не
полосой, висящей между двумя половинами; общая отбивка `.territory__rule` перебита
целиком, а не одним краем: в шапке блока она несимметрична в другую сторону, там
под линией стоят подписи. Под дивайдером три дорожки: кадр, поле, список.
**Список занимает ровно половину экрана** — `50%` от колонки страницы, а она
центрирована, поэтому её половина и есть середина экрана; доли вместо процента
сюда не годятся. Междурядья между дорожками нет вовсе: гэп отодвинул бы границу
списка от середины на свою половину, отбивку держит средняя дорожка — она и есть
поле. Кадр — пять колонок из двенадцати, та же ширина, что у кадра закрывающего
блока: два разных размера на одной странице читаются ошибкой. Проценты в дорожках
считаются от самой сетки, поэтому выражение и стоит в `grid-template-columns`, а
не на кадре — там оно дало бы долю его собственной половины. Описание встаёт по
ширине кадра само: оно лежит в той же дорожке. Отбивка от сцены выше —
максимальная в шкале
(`--space-10xl`): блок после трёх экранов пина обязан читаться новым, а не её
продолжением. Кадры — те же рендеры легенд, и соответствие не случайное: рендер
каждой сделан вокруг своего объекта (`legends[].object` в манифесте). Пятый
объект — исток Ангары; его текст держится географии, которая уже стоит в подписях
блока, потому что фактология территории по-прежнему приходит от заказчика. Класс
`obj`, а не `card`: `card` — это карточка легенды в сцене, и одинаковые имена в
двух блоках путают при отладке даже при скоупе Astro.

**Пара «название — кадр» лежит в разметке рядом, а по колонкам её разводит
сетка** (`li` раскрыт `display: contents`). Разнесённые по двум спискам, они
разъехались бы порядком чтения, а на узком экране их пришлось бы сшивать обратно
скриптом; здесь узкий экран — это `display: block` на пункте и больше ничего.
Кадры все лежат в одной ячейке друг на друге и спанят список целиком, поэтому
строк в сетке ровно столько, сколько объектов (`--rows` из разметки), плюс одна
гибкая в хвосте: `grid-row: 1 / -1` требует явных строк, а избыток высоты кадра
уходит в гибкую дорожку, а не растаскивает названия по своей высоте.

**Показанный объект держит класс, а не `:hover`.** Курсор ушёл с названия —
кадр остался. Чистым CSS (`:has(:hover)`) это не выражается: без наведения
пришлось бы возвращать первый объект, и увод курсора в сторону кадра сбрасывал бы
показанный. Первый пункт помечен активным на сервере, поэтому без JS блок
остаётся рабочим. Названия — кнопки, и фокус ведёт кадр наравне с курсором: иначе
с клавиатуры видно ровно один объект из пяти. На 900 двух колонок нет вовсе —
объект собирается обратно в карточку (название, кадр, описание), и показаны все
сразу.

**Закрывающая мысль стоит на двух колонках: слева набор, справа портретный
кадр.** Линий у неё нет ни одной — ни сверху, ни внутри: от объектов её отбивает
пустое поле в максимальный шаг шкалы (`--space-10xl`), а дисплейный заголовок
начинает блок сам. Своей ссылки у блока тоже нет: условия открывает кнопка блока
ниже, и вторая кнопка на то же место читалась бы дублем. Заголовок стоит по верхней
кромке, текст — по нижней: высоту ряда задаёт пропорция кадра (2:3), и низ обеих
колонок обязан сойтись. Доли колонок 7:5, а не поровну: на равных дисплейный
заголовок ломался бы на вдвое большее число строк. Мера текста ограничена в `ch` и
стоит на самих абзацах, а не на обёртке: `ch` считается по кеглю элемента, а
обёртка набрана крупнее — на ней те же 72ch дали бы меру шире колонки, то есть не
дали бы ничего. Кадр — маяк, единственный рендер, не занятый в объектах выше:
повтор на одном экране читается ошибкой вёрстки, а не приёмом. Отбивка между абзацами
`--space-2xl`, и это не вкус: набор идёт с вертикальным trim, бокс абзаца обжат по
кап-высоте, и 16 px между ними дают тот же просвет, что между строками внутри
абзаца — два абзаца читаются одним.

**Карточки легенд и мини-плашка собраны по макету заказчика**: обе — бумажные
панели без скругления, со своей темой `light` на самом узле (кадр легенды под
ними тёмный, и цвет текста обязан приходить не от темы секции). В полной
карточке номер, заголовок и дивайдер стоят по центру, легенда и факт лежат в
двух колонках, снизу кнопка «Подробнее» на `/legends/<id>` — страниц легенд ещё
нет, ссылка ведёт в 404. Номер мини-плашки — порядок точки в `points.json`; он
же номер карточки, потому что порядок в манифесте и `order` в контенте — одна
нумерация.

**Вход обеих карточек рисует клип, уход — прозрачность.** Смена легенды и есть
смена карточки: предыдущая гаснет прямо под наплывом, следующая раскрывается
`clip-path` сверху вниз, а текст входит построчно со стаггером. Условие показа —
не «какая легенда», а «какая легенда, у которой наплыв прошёл больше половины»:
на границе слотов оно само даёт паузу, в которой старая карточка уходит.
Затухание на входе выключено (`transition: none` у `.is-in`) — иначе оно
смазывает фронт, ради которого клип и взят.

Карточка легенды раскрывается от середины в обе стороны (0.8 с, `--ease-expo`),
внутренности входят целыми блоками одной очередью: номер, заголовок, дивайдер,
обе колонки, кнопка. Порядок — атрибутом `--i` в разметке, а не счётчиком в
скрипте: элементов ровно столько, сколько видно в шаблоне. Мини-плашка идёт тем
же ходом, только сверху вниз и быстрее.

Построчный вход из карточки убран заказчиком. `hero/lines.ts` — разбивка текста
на настоящие строки измерением — работает в сцене «О территории», а карточка
входит целыми блоками.

Карточка ходит по слоту от середины кадра в обе стороны (`--y`, +1 → −1, концы
сглажены `smooth01`), а её дивайдер — заодно прогресс легенды: акцентная полоса
слева направо по `--p`. Линия у него фоном, а не бордером: у `hr` браузерный
`overflow: hidden`, и полоса поверх бордера обрезается целиком. Высота карточки
фиксированная (`clamp(34rem … 38.5rem)`) — подстройка под длину текста
превращала бы смену легенды в подскок панели.

Отступы внутри обеих карточек назначены поштучно каждому элементу. Сброс вида
`.card p { margin: 0 }` специфичнее классов элементов и молча съедает их
собственные margin, а весь текст набран с вертикальным trim и без отступа встаёт
кап-высотами вплотную. По той же причине у `hr` явно стоит `margin-inline: 0`:
браузерный дефолт `auto` в гриде ужимает линию до нулевой ширины.

**Первый экран собран по макету заказчика**: хедер (меню, леттеринг-логотип,
кнопка заявки), заголовок, дивайдер, три подписи под ним и подсказка прокрутки.
Всё на токенах, тема `brand` стоит на самой секции. Карточки легенд и
мини-плашка у метки остались прежними — их модернизируют отдельно.

**Точки легенд — метки, а не светлячки.** Плотный кружок акцентного цвета с
чётким краем, лёгкий рассинхронный пульс; под курсором метка ужимается и
размывается, уступая место самому огню. Аддитивное свечение убрано вместе с
очередью зажигания: мишень, которая разгорается, читается как ещё не готовая
к нажатию. От метки расходится кольцо-радар — оно идёт по тому же счёту, что и
пульс, чтобы метка читалась одним биением, а не двумя.

**Метки собираются в счётчик легенд.** Всю дорогу от начала раскрытия до первой
легенды шесть точек летят в одну — на место плашки у левого края, по центру по
вертикали. Там сцена снимает их целиком, и ровно в той же точке встаёт DOM:
тот же круг того же цвета. Подмена мгновенная и без кроссфейда — два
полупрозрачных круга друг на друге дают мигание. С первой легендой круг
разворачивается в плашку «Собрано N из 6 легенд», и счёт **только растёт**:
отмотка вверх возвращает кадры, но не отбирает собранное.

Место плашки назначает DOM, а не сцена: она стоит по общей колонке страницы
(`u-container`), сцена спрашивает её `target` и ведёт точки туда. Диаметр круга,
наоборот, приходит из сцены (`Scene.dotPx`) — прилетевшая метка и вставший круг
обязаны быть одного размера. Оба числа живут по одному разу.

**Кадры легенд — настоящие рендеры, но их четыре на шесть легенд.** Файлы лежат
в `key-visual/legends-results/`, соответствие — `LEGEND_SOURCES` в `kv/config.py`
(разовая подмена — `--legend-src <id>=file.png`). Повторы стоят через один:
соседние слоты обязаны отличаться картинкой, иначе наплыв читается техническим
швом. Рендер приходит 16:9 и проходит в `legendframes.py` тот же путь, что
мастер: рампа KV, центр канваса на `LEGEND_FIT` = 92% ширины, поля вокруг общей
с `pad` функцией, своя карта глубины Depth Anything в альфу.

Число 92% — не «на глаз»: рендеры шире канваса по пропорции, и вписанные по
видимому кадру они оставляли бы поля сверху и снизу на экранах уже 16:9. Здесь
наоборот, по краям срезается — зато кадр заполнен на всех ходовых пропорциях.

**Гамма у каждого кадра своя, подобранная под медиану мастера** (`duotone.
match_gamma`). Растяжка по перцентилям выравнивает диапазон, но не среднее:
рендеры сняты с разной экспозицией, и на общей гамме один кадр выходил заметно
бледнее соседнего — в ленте это читается сменой тона, а не сменой сцены.

Id, для которого рендера нет, по-прежнему собирается заглушкой из мастера:
крупный план вокруг огня легенды в геометрии канваса.

Чего нет: звук (ТЗ 1.8) и кнопка его регулировки, живые детали в кадре (спрайты
сгенерированы, в сцену не заведены), depth на контентных изображениях (ТЗ 2.5),
внутренние страницы и форма заявки (`/competition`, `/competition/rules`, `/apply`,
`/voting`, `/voting/results`, `/privacy`, `/legal`, `/legends/<id>` — на них уже
ссылается главная), механизм, который назначает состояние голосования вместо
временного переключателя.

**Адаптив страницы под сценой сведён и проверен** от 320 до 1920: горизонтальной
прокрутки нет ни на одной ширине. Держат его текучие токены (кегли и шкала
отступов — прямые от 360 до 1440 с продолжением до 1920) и три порога раскладки,
и других заводить не надо: **1100** — три дорожки «О конкурсе» и боковые кадры
голосования, **900** — все двухколоночные блоки в одну колонку и коллаж сцены
«О территории», **560** — кнопки и подписи в столбец. Порог 900 тот же, на
котором первый экран отпускает пин.

**Ось блока на узком экране одна.** Дисплейный заголовок и дивайдер стоят по
центру, поэтому в одну колонку туда же встают и подписи «О территории», и условия
«О конкурсе» с абзацами и кнопками, и кадр с текстом «О проекте». По левому краю
под центрированной шапкой блок распадается на центрированный верх и левый низ.
Абзацам при этом центрируется бокс (`margin-inline: auto`), а не строки: выключка
по формату остаётся, она же и есть условие центровки — при рваном правом крае
масса текста стоит левее центра.

**Раскрытия панорамы на узком экране нет вовсе.** Ход `territory-open` лежит под
`(min-width: 901px)`: кадр там во всю колонку и невысокий, четверть подреза
съедает его почти целиком, подпись-оверлей на полпути стоит посреди обрезанного
кадра, а диапазон кончается на верхней кромке экрана — раскрытие читается не
раскрытием, а недогруженной картинкой. На компьютере ход остаётся и трогать его
нельзя.

**Лишний `*/` в CSS компонента гасит правило молча, и виновата будет не та
правка.** Дописанный к комментарию абзац уехал за его закрывающую пару, и текст
оказался на верхнем уровне таблицы стилей: парсер снёс следующий за ним блок
`@supports` целиком — раскрытие панорамы пропало не на телефоне, где его и
снимали, а на компьютере. Ни ошибки в консоли, ни падения сборки: `astro check`
CSS не смотрит, `npm run check` ловит только ошибки сцены. Правя комментарий
перед правилом, смотреть, где стоит `*/`, — и проверять само правило
`getComputedStyle`, а не глазами по соседнему блоку.

Четыре вещи в этом адаптиве неочевидны, и каждая уже ломала блок молча.

**Грид без `grid-template-columns` не растягивает содержимое.** У кнопок
«О конкурсе» на ≤560 стоит `display: grid` с `justify-self: stretch`, и без явной
дорожки `minmax(0, 1fr)` растягивалась сама сетка, а кнопки оставались по
контенту (замер на 390: 150 px при колонке 366).

**Поп-ап переключателя голосования отсчитывается от иконки, а не от секции.**
На ≤900 переключатель уходит в поток, и `position: static` там ставить нельзя:
поп-ап лежит абсолютом, и на статичном родителе его `inset-inline-start: 100%`
считался бы от ширины секции — замер давал левую кромку на 398 при экране 390.
Стоит `relative` с явно снятыми отступами базового правила, а сам поп-ап на
узком экране раскрывается вниз, а не вправо.

**Коллаж сцены «О территории» на узком экране не уходит, а переезжает, и
геометрия у него своя — вторая.** На широком кадры стоят по краям и обходят набор
слева и справа; на узком набор идёт во всю колонку, места сбоку не остаётся вовсе,
и там кадры превращались в полоски в палец (из-за чего их когда-то сняли совсем).
Свободна на узком только верхняя полоса стенда — замер: заголовок начинается на
29–41% высоты (375×667 … 900×700), а низ занят текстом почти до кромки (на
375×667 до 91.6%). Поэтому все три кадра слайда собираются в кластер над
заголовком.

Три условия этого кластера. **Размер задаётся высотой, а не шириной** (`--mh` в
долях стенда, ширину доводит пропорция): доля ширины на широком-коротком экране
(900×700) дала бы кадру 3/4 высоту в полтора стенда, то есть поверх всего набора.
**Ход композиции там короче** — `--drift` 8svh против 25: на широком кадры
разнесены по всей высоте и полэкрана хода им не мешают, а кластер на том же ходу
сметало за верхнюю кромку раньше, чем его успевали увидеть (замер на 390×844: к
середине пина кадры стояли на −120…124, приходящий коллаж второго подблока не
показывался вовсе). **Слой кадров обрезан** (`overflow: clip` на `.story__shots`,
не на стенде — набор лежит в соседнем слое): ширина кадра приходит от пропорции и
в процентах не известна, и без клипа плашка у правой кромки давала бы
горизонтальную прокрутку всей страницы. Зазор до заголовка от хода не зависит и
замерен: 17 px в худшем случае (900×700), 76–130 на телефонах.

**Сцена «О территории» отдаёт стенд, когда не влезает в экран.** Стенд залипает
ростом ровно в `100svh`, обрезать перебор нечем — сцена лежит в потоке, и лишнее
полезло бы на соседние блоки. Поэтому скрипт после разбивки меряет каждый
подблок (`scrollHeight` против `clientHeight`) и при переборе снимает
`data-story-split`: блок читается стопкой — тем же состоянием, что при
`prefers-reduced-motion`. Замер, а не порог по высоте: высота набора зависит и от
ширины, и от кегля. Сцена остаётся на всех ходовых телефонах в портрете (от
375×667) и отдаётся на 320×568, 360×640 и на телефоне лёжа. Строки при отказе
обязаны вернуться в исходную разметку (`restore` в `hero/lines.ts`): они лежат
отдельными спанами без пробелов между ними, и в потоке слиплись бы в одно слово
на каждом переносе.

**Вертикальная перекадровка заморожена** заказчиком до работ по адаптиву — в
контекст не брать. Сцена первого экрана в этот проход адаптива не входила вовсе.

Открытые вопросы — всё, что приходит от заказчика и намеренно не выдумано:
данные завода для карточки `factory`, сроки приёма заявок и число финалистов
(«уточняется» в `Competition.astro`), дата старта голосования (`STARTS_AT` в
`Voting.astro`), логотипы четырёх групп, контакты и соцсети в футере, фото или
панорамное видео территории вместо кадра кей-вижуала.
