# Сайт

Astro, статическая сборка. Первый экран — один островок на OGL, всё остальное zero-JS.

```bash
npm install
npm run dev              # http://localhost:4321
npm run build
npm run check            # прогон сцены в браузере: фазы, ошибки, скриншоты в shots/
npm run check:legends    # прогон ленты легенд: индексы слотов, наплывы, карточки
```

`npm run check` поднимает Chromium, проходит все три фазы сценария и печатает
отчёт: режим сцены, размер канваса, число точек и карточек, список ошибок
консоли и сетевых сбоев. Пустой `errors` — сцена собралась. Скриншоты фаз
ложатся в `shots/` и в git не идут.

## Откуда берутся ассеты

Их не правят руками и не кладут в репозиторий вручную. Всё в `public/kv/`
пишет стадия `web` пайплайна:

```bash
cd ../key-visual/pipeline
../.venv/bin/python build.py dist/master/master-toned.png --only web
```

| Что | Зачем |
|---|---|
| `plates/p{1,2,3}-*-{ширина}.{avif,webp}` | плашки параллакса, геометрия всего канваса |
| `plates/fog-*.webp` | форграунд под маской: RGB — размытая копия канваса, A — контурная калька |
| `maps/depth-emission.webp` | R — глубина, G — источники света, B — калька в расфокусе |
| `sprites/*.png` | шум для маски, луч, дым, поезд |
| `kv-*.{avif,webp}` | готовые кропы: статичный кадр и фолбэк |
| `points.json` | шесть точек: UV канваса, глубина, проценты кропов |
| `manifest.json` | вся геометрия: доли видимого кадра, границы планов, бюджет хода |

**Ни одно из этих чисел не продублировано в коде фронта.** Поменяются доли или
пороги в `kv/config.py` — сцена подхватит их после пересборки. Единственное, что
связывает пайплайн и контент, — `id` легенды: он одновременно ключ в `LEGENDS`
и имя файла в `src/content/legends/`.

## Как устроен первый экран

```
src/hero/
  index.ts      сборка: один rAF на всё, ввод, монтирование
  state.ts      общее состояние — его читают шейдер, точки, скролл
  caps.ts       WebGL, reduced-motion, DPR, выбор тира текстур, замер FPS
  scene.ts      OGL: геометрия кадра, два прохода, метки легенд
  shaders.ts    квад сцены, формула маски и инстансный проход меток
  textmask.ts   снимок маски в mask-image для тёмной копии текста
  blob.ts       пятно: инерция, магнетизм, автономный дрейф
  points.ts     прозрачные кнопки поверх огней и мини-карточка
  tally.ts      плашка счётчика: в неё слетаются метки, в ней растёт счёт
  gate.ts       экран входа: выбор звука, запуск сцены, пауза прокрутки
  scroll.ts     ScrollTrigger: пин, три фазы сценария, перекрытие секции
  fallback.ts   без WebGL: backdrop-filter и радиальная маска
```

Плавная прокрутка живёт отдельно от сцены — `src/lib/smooth.ts`, поднимается из
`Base.astro`. Раньше экземпляр Lenis создавал `hero/scroll.ts`, и на страницах
без первого экрана инерции не было вовсе. Экземпляр один и идемпотентный: второй
Lenis на том же документе даёт два сглаживания одного скролла, то есть дёрганую
прокрутку. Сцена его только подписывает (`onSmoothScroll(ScrollTrigger.update)`)
и придерживает на экране входа (`stopSmooth`), а `destroy` пина снимает подписку,
но не убивает прокрутку. При `prefers-reduced-motion` инерции нет — прокрутка
остаётся обычной.

Система координат одна — **UV всего канваса, включая поля**. Экранные позиции
считает `scene.frame()`, и через него же проходят DOM-кнопки: поэтому кнопка
физически не может отклеиться от своего огня.

## Дизайн-система

Токены живут в `src/styles/tokens/` и подключаются одним файлом
`src/styles/tokens.css`, который импортирует `global.css`. Витрина —
`/tokens`: все группы разом, числа читаются из вычисленных стилей и меняются
при ресайзе окна.

```
tokens/primitive.css   0. сырые цвета, прозрачности через rgb(... / a)
tokens/theme.css       1. bg/surface/fg/muted/border/accent × light|brand|accent
tokens/space.css       2. отступы компонентов, текучие
tokens/radius.css      3. скругления, фиксированные
tokens/section.css     4. поля страницы и ритм секций, текучие, две ветки
tokens/type.css        5–7. кегль, интерлиньяж, трекинг, вес, гарнитура
utilities.css          классы u-*, значение всегда токен
kv.css                 рампа кей-вижуала — НЕ дизайн-система
```

**Слои вместо !important.** `@layer tokens, base, utilities` в `global.css`:
утилита бьёт базовый стиль тега не специфичностью, а порядком слоя, поэтому
`.card .title` больше не перебивает `.u-text-main`. Стили компонентов Astro
лежат вне слоёв и бьют оба — на то они и локальные.

**Компонент берёт токен темы, а не примитив.** Девять имён из `theme.css`
переключаются атрибутом `data-theme` на любом узле, и узел с темой сразу
красится сам. Прямая ссылка на `--coral` или `--dark-blue` в компоненте
означает, что он не переживёт смену темы — молча, без единой ошибки.

**Колонка страницы — одна на весь сайт.** `u-container`: поля `--margin` и
потолок `--page-max` = 1920, дальше блок стоит по центру. Свой `max-width`
у секции значит, что при первой же правке она отстанет от соседних, и разница
читается ступенькой по краю страницы. Первый экран живёт в той же колонке:
кадр во весь экран, но текст на нём стоит по общим полям.

**Дивайдер один на весь сайт.** `styles/rule.css`, класс `.rule`: линия фоном
(у `hr` браузерный `overflow: hidden`, и полоса прогресса поверх бордера обрезалась бы
целиком), `margin-inline: 0` против браузерного `auto`, который в гриде ужимает линию до
нулевой ширины, и пара отбивок — `--space-lg` сверху, `--space-xs` снизу. Числа взяты с
первого экрана: там пара «заголовок → линия → подписи» и есть эталон.

Берут его все семь мест: первый экран, карточка легенды, «О территории» (обе линии),
«О конкурсе», три панели голосования, «О проекте». В футере линии нет вовсе — заказчик
её снял, части там разводит пустое место. Замер после сведения — 24 и 12
у каждой на 1440. До этого у каждого блока была своя пара (от `xl`/`md` до `6xl`/`xl`), и
«одинаково» держалось ровно до следующей правки. Блоку остаётся только своя роль: цвет
`--fg` у первого экрана (линия лежит поверх кадра, а у тёмной копии под маской цвет свой)
и `position: relative` у карточки, где дивайдер заодно полоса прогресса легенды.

**Текучесть — прямая, а не ступени.** Опоры 360 и 1440, дальше та же прямая
продолжается до 1920 и упирается в потолок `clamp`. Число из макета лежит на
прямой ровно. Исключение — группа `section`: там в макете три ширины
(375/768/1440), и кривая между ними ломаная — `margin` растёт вдвое быстрее до
768, `section-lg` наоборот почти стоит. Одной прямой это не описать: промах на
768 доходит до 25 px. Поэтому два отрезка со стыком на 768, значения на стыке
совпадают.

Мелкие шаги (`space-3xs`…`space-md`, все радиусы) не текут: отступ в 4 px,
ужатый до 3, — это не адаптив, а дрожание.

Кегли на 360 ужимаются тем сильнее, чем они крупнее: 112 → 40, но 20 → 18.
Заголовок, ужатый пропорционально мелкому тексту, занимает на телефоне
пол-экрана.

**Текстовый стиль назначается целиком.** `u-text-style-*` кладёт разом кегль,
интерлиньяж, трекинг и вертикальный trim. Порознь их не ставят: кегль без
своего интерлиньяжа даёт заголовок, разъехавшийся по высоте строк. Имена
кеглей — из макета (`h-4xl`…`h-sm`), имена стилей — уровнями (`display`,
`h1`…`h6`, `text-xl`…`text-sm`, `eyebrow-md`…`xs`); таблица соответствия
в шапке `tokens/type.css`.

Заголовочные теги `h1`–`h6` уже выглядят своим уровнем без класса: medium,
капслок, свой интерлиньяж и трекинг. `u-text-style-*` нужен там, где уровень
разметки и уровень оформления не совпадают.

**Вертикальный trim включён у всего текста** (`text-box-trim: trim-both`,
`text-box-edge: cap alphabetic`) — блок встаёт по кап-высоте и базовой линии,
как в Figma с включённым vertical trim. Следствие: полуинтерлиньяжа больше
нет, и строки, стоящие стопкой, разводятся `gap`-ом, а не «само получится».
Браузеры без поддержки правило игнорируют.

Manrope подключён вариативным (`@fontsource-variable/manrope`, кириллица в
сабсете), вес назначается токеном `--weight-*`. Абзац по базовому стилю идёт
полужирным: на тёмном фоне и мелких кеглях regular расплывается. Там, где на
абзаце стоит `u-text-style-*`, вес приходит из стиля — он назначается целиком,
и поверх него ставится `u-weight-semibold`.

## Решения, которые стоит знать

**Кадр всегда во весь экран.** Кашетированной полосы нет ни в одной фазе:
раскрытие — это уход тумана и ход камеры, а не смена кадрирования. В тумане
охват равен видимому кадру: поджимать нельзя, при 0.72 маяк на 0.816 ширины
выпадал за экран, а все шесть точек обязаны быть доступны с первого экрана.

**На раскрытии камера уходит ЗА видимый кадр**, до 1.12 — иначе сцена целиком не
помещается. Захваченные при этом поля дорисованы моделью и резкими быть не
должны, поэтому кромка на 7% с каждой стороны уводится в размытую копию. Читается
как продолжение тумана, а не как край картинки. В фазе тумана кромка уходит не в
неё, а в саму кальку: калька лежит на всём экране, и светлая размытая рамка по
её краю читается браком.

**Вертикаль в шейдере считается от НИЗА.** Текстуры грузятся с `flipY`, поэтому
`v` растёт вверх, а точки, курсор и DOM живут в координатах от верха. Пересчёт
лежит в одном месте — `screenOf` и `screenUv()` в шейдере. Пока его не было,
маска ходила по Y навстречу мыши, а светлячки уезжали от своих огней.

**Плашки друг относительно друга не двигаются вообще.** Любой их взаимный сдвиг
рвёт кадр: граница планов идёт по кромке леса, и по обе стороны от неё лежит одна
и та же местность из двух разных файлов — сдвинул один, получил ступеньку.
Коэффициенты `PLANE_PARALLAX` в конфиге остались, но амплитуда нулевая.

**Весь параллакс делает попиксельный изгиб по глубине.** Он непрерывный, порваться
не может, и дальнее уходит вниз сильнее ближнего — то самое «задний план заезжает
за передний». Выше определённого предела начинают деформироваться здания и насыпь:
смещение растягивает текстуру там, где глубина рвётся. Подобранное значение
`BEND_GAIN` — в [CLAUDE.md](../CLAUDE.md), там же остальные настроенные числа.

**Параллакс за мышью — с большим запаздыванием.** Заметный читается как дешёвый
трюк и мешает целиться в светлячок. Размытая копия смещается вместе с резкой:
иначе фон едет, размытый передний план стоит, и выходит каша.

**Фоновый рой выключен.** Шесть смысловых точек в нём терялись, а лишние светлые
пятна читались как брак кадра. Константа `SWARM_FULL` в `scene.ts` — включается
одним числом.

**Экран входа держит сцену закрытой.** `state.enter` = 0 — форм кальки нет
(`uFogIn`), пятна нет (нулевой радиус смыкает маску на весь экран). Вход ведёт
оба шага одним ходом: калька проступает из прозрачности и расфокуса (тот же
готовый уровень, что размывает верх кадра, — лишних выборок проявление не
стоит), следом растёт окно, следом входят строки. Отсечки — `ENTER_FOG` и
`ENTER_HOLE`, они перекрываются: без перекрытия между шагами появляется пауза.

**Сценарий скролла поднимается до входа.** Pin переставляет узлы, а перестановка
сбрасывает запущенные переходы — созданный по клику, он обрывает и уход экрана
входа, и ход строк. Прокрутку на это время держит `Scroll.stop()`, то есть
Lenis: `overflow: hidden` прячет скроллбар, меняет ширину вьюпорта и требует
`ScrollTrigger.refresh()`, а refresh — это ровно та перестановка узлов, от
которой уходили.

**Строки первого экрана размечены, а не измерены.** Переносы здесь дизайнерские,
те же, что были `<br>`, и очередь входа задана атрибутом `--i` в разметке — как
у карточек легенд. `lines.ts` (разбивка измерением) по-прежнему не подключён.
Ход входа ловит и обе копии текста под маской: они лежат в том же слое, а класс
стоит на общем родителе — три копии стартуют в один кадр.

**Текст первого экрана лежит в двух слоях.** Верхний — выворотка на кальке,
нижний — цветом фона, и открывает его та же маска, что открывает кадр: снимок
дыры уходит в `mask-image` копии.

Копий текста две, и показана всегда одна. Смена `mask-image` у видимого слоя
даёт кадр без маски, а слой без маски виден целиком — вспышка тёмного текста на
весь экран. Поэтому снимок всегда идёт на скрытую копию, декодируется, и только
через два кадра копии меняются местами; прошлый адрес отзывается ещё позже, он
до сих пор нарисован. У копий снят переход прозрачности: подмена идёт каждые
45 мс, и полусекундная анимация от общего правила слоя не успевает доиграть —
именно она и читалась как мерцание. Форма дыры процедурная, её считает шейдер по
шуму, и повторить её в CSS нечем — круг под текстом появлялся бы не там, где
действительно светлое небо. Снимок берёт свой маленький канвас (`textmask.ts`),
не чаще чем раз в 45 мс: маска идёт за курсором, отставание на кадр в ней не
читается, а полный кадр стоит кодирования PNG.

**Форграунд в тумане — двухцветная калька, а не размытая копия.** За маской
лежит тот же кадр плоским фоном темы и белыми формами: контур ландшафта и белые
массы шести объектов-легенд. Размытие показывало ту же картинку, только хуже;
калька показывает другой её слой. Оба цвета приходят из токенов темы `brand`
(`--bg` и `--fg-highlights`), в шейдере их нет числами — калька обязана
пережить смену палитры. Выборка у кальки та же, что у резкого кадра: тот же
изгиб по глубине, тот же параллакс за курсором. Иначе на краю маски шириной в
пиксель контур разъезжается со своим объектом.

**Верх кальки расфокусирован**, тем сильнее, чем ближе к кромке, и до нуля к
первой гряде верхушек. Размытый уровень приходит готовым — синим каналом карты
глубины, — а промежуточная сила получается смешиванием с резкой калькой из
альфы форграунда. Считать размытие выборками в шейдере нельзя: на тонком
контуре даже дюжина выборок читается веером призраков, а не расфокусом.
Размывается покрытие, а не готовый цвет: размытый цвет тащит за собой фон и
даёт светлую вуаль там, где форм нет вовсе.

**Размытая копия осталась, но живёт в альфе кальки.** Ею уходит в расфокус
кромка, когда камера отъезжает в поля, — и на это нельзя тратить второй
текстурный юнит: восемь заняты все. Поэтому `plates/fog-*` — одна текстура на
две карты, тот же приём, что у кадров легенд с глубиной. Тонировки у копии нет:
кромку уводит в светлое сам шейдер (`RIM_LIGHT`, цвет из токена), и чем ближе
к краю, тем больше подмес. Подмес тени, из-за которого копия темнела, был нужен,
пока ею закрывался весь кадр под маской; с калькой он давал по краям виньетку.

**Размытых плашек не существует.** В фазе 1 параллакса ещё нет, в фазе 2
размытие уже ушло, а композит плашек в покое совпадает с мастером с точностью
0.01% — поэтому резкий композит можно мешать с одной размытой копией канваса в
любой момент, шва не будет.

**Светлячки — второй проход, а не часть кадра.** Аддитивный инстансный квад на
точку. Мягкость каждого считается по расстоянию до пятна в вершинном шейдере:
честнее было бы рендерить их в отдельный буфер и размывать, но на экране разницы
нет, а лишний проход стоит кадра.

**Точка едет с тем планом, на котором сидит.** Глубина в точке приходит из
`points.json`, по ней выбирается коэффициент параллакса. Без этого светлячок
уезжает от своего огня на первом же движении камеры.

**Радар и сборка живут в том же проходе.** Кольцо расходится от кромки метки за
её квад, поэтому квад метки расширен (`DOT_RING.x`), а `vQuad` остаётся в
радиусах самой метки — 1.0 всегда её край. Фаза кольца берётся от счёта пульса,
а не заводит свои часы: два независимых такта на одном кружке читаются
дребезгом. На раскрытии те же метки слетаются в одну точку (`state.gather`,
своя задержка у каждой), и когда сборка кончилась, сцена снимает их целиком —
на их месте уже стоит плашка счётчика.

**Счётчик легенд — DOM, но его место и размер согласованы со сценой.** Плашка
стоит по общей колонке (`u-container`), сцена читает её `target` и ведёт точки
туда; диаметр круга, наоборот, приходит из сцены (`Scene.dotPx`), иначе подмена
канваса на DOM даёт скачок размера. Круг разворачивается в плашку через
`grid-template-columns: 0fr → 1fr` — ширину `auto` не проанимировать, а
измерять её скриптом значит завести второе место, где живёт та же ширина.
Счёт монотонный: `Math.max` по уже показанному, отмотка вверх его не отбирает.

**Финальный наплыв — тот же переход, но открывает он страницу, а не картинку.**
За последней легендой фронт снимает канвас в прозрачность (`alpha: true` у
рендерера, шейдер отдаёт `1.0 - outro`), и в дыру видно настоящую секцию
«О территории». Заливки цветом у финала больше нет: рисовать фон следующего блока
значит держать его цвет вторым числом рядом с токеном темы, а под дырой лежит и
сам фон, и текст на нём. Форма фронта общая с легендами — `dissolveWipe`
принимает прогресс и зерно аргументами, потому что вторая формула для той же
кромки разъехалась бы с этой. Уходящая легенда гаснет под ним тем же
`LEGEND_DIM`, что и любой нижний слой.

**Секция под сценой поднимается сама, обычным скроллом.** Пока идёт финальный
слот, она едет снизу вверх ровно настолько, насколько прокручено: своей анимации
у этого движения нет вовсе. Делает это перекрытие — `margin-block-start:
calc(var(--hero-h) * -1)` на секции, атрибут `data-hero-overlap` на `:root`
ставит `hero/scroll.ts`. Три следствия, которые нельзя развязывать:

- **Перекрытие равно высоте сцены и равно длине финального слота.** Пин
  отпускает через `screens` экранов, и секция окажется по верхней кромке только
  если поднята ровно на свой экран. Высота живёт один раз — `--hero-h` в
  `Hero.astro`; `OUTRO_SCREENS` = 1 в `scroll.ts` — второй конец той же связи.
- **Фона под канвасом нет ни на секции сцены, ни на её слое.** Фон приходит от
  `data-theme="brand"`, и именно он перекрывал страницу под дырой: снимается тем
  же атрибутом `data-hero-overlap`, то есть только в режиме WebGL. Фолбэку фон
  остаётся — под ним картинка, а не прозрачный канвас.
- **Порядок слоёв задан явно:** `.hero` — `z-index: 1`, секция под сценой —
  `position: relative; z-index: 0`. Позиционированная без своего слоя, она стоит
  в разметке позже и легла бы поверх канваса, накрыв кадр вместо того, чтобы
  открыться из-под него.

Фронт наплыва рваный, с разбросом `TEAR` в 0.85 экрана, и его острова уходят
выше того места, куда секция уже доехала. Поле над её кромкой рисует `::before`
той же высоты — без него в островах просвечивал бы фон страницы с рампы KV, то
есть тёмное пятно поверх открывшейся светлой секции.

Слой сцены при этом не ловит указатель (`pointer-events: none` на `.hero__stage`,
интерактив внутри включает себе сам): прозрачный канвас остаётся поверх
открывшейся секции, и невидимый перехватчик забирал бы у её текста и клик, и
выделение.

**На финале прокрутка не прерывается.** Кадр легенды уезжает вверх
(`OUTRO_LIFT`; потолок задан запасом текстуры под `LEGEND_INSET`, за ним пойдёт
тянущийся последний пиксель), карточка уходит туда же через `--out` и гаснет
вдвое быстрее — доехать до кромки поверх открывшейся страницы ей нечем. Наплыв
занимает слот целиком, без `WIPE_SHARE`: стоять после него нечему.

`state.outroRise` — докуда снизу канвас снят гарантированно: тот же порог, что
в шейдере, взятый в худшем случае поля. Текста, который по нему ехал, больше нет,
и число осталось замером — его печатает `check:legends` вместе с `terr`, верхней
кромкой секции: к концу пина она обязана встать на ноль, и разъехавшееся
перекрытие видно только числом — на скриншоте два светлых экрана неотличимы.

**Окно кадра зажато границами канваса.** За краем текстура тянется последним
пикселем и даёт полосы поперёк кадра. Запас поверх полуразмера берётся из
бюджета хода в манифесте, а не подбирается на глаз.

**Фолбэки — часть каркаса, а не «потом».** Без WebGL работает CSS-размытие с
радиальной маской, при `prefers-reduced-motion` — статичный кадр, без JS —
обычная страница с текстом первого экрана и секциями под ним. Точки-легенды
всегда настоящие `<button>`.

Текстового списка легенд под сценой больше нет: `LegendList.astro` удалён
заказчиком. Следствие — полного текста легенд без JS и при
`prefers-reduced-motion` на странице не остаётся, карточки живут только в
скролл-сценарии.

### Фотографии-заглушки и параллакс (временно)

На местах будущей съёмки стоят обычные ландшафтные фотографии, а не рендеры
легенд: по рендеру не видно ни кропа, ни параллакса, ни того, как блок будет жить
с настоящим кадром. Соответствие «место → файл» и выключатель — `src/lib/photos.ts`
(`PHOTOS = false` возвращает пайплайн, прежние выражения с манифестом стоят в
компонентах рядом). Файлы пишет `scripts/placeholders.mjs`, в `public/placeholder/`
руками не кладётся ничего. Уходит всё это одним движением: скрипт, модуль, папка
и `styles/photos.css`.

Параллакс живёт в `styles/photos.css`, класс `.photo` на боксе кадра. Прогресс
считает браузер по `view()`-таймлайну, диапазон `cover` — всё время, пока бокс
виден хоть краем; своего слушателя скролла нет намеренно, рядом с Lenis он был бы
вторым и на каждый кадр. Ход — `scale: 1.3` с `translate` ±11.5% (при 1440 это
±43 px у кадра объекта, ±89 у панорамы, ±97 у портретного). Числа связаны:
`translate` применяется до `scale`, поэтому фактический сдвиг равен произведению и
обязан укладываться в запас `(zoom − 1) / 2` — сдвинешь больше, из-под кадра
покажется край бокса. Базовое состояние без таймлайна — кадр по центру и без
хода: иначе та же анимация проиграла бы по обычному времени и уехала в свой конец
насовсем.

Картинка внутри бокса лежит **абсолютом**, и это не стилистика. В потоке она
отдаёт боксу свои интринсик-размеры — и высоту, и ширину при этой высоте: бокс
панорамы уезжал за колонку страницы на 170 px (min-content дорожки грида), а
портретный кадр терял 40 px высоты ряда, причём обе поломки видны только замером.
Абсолют в интринсик-размеры не попадает, и бокс считается только по своей
пропорции. Пропорция поэтому стоит на боксе, а у закрывающего кадра — на его
ячейке: ячейка и есть элемент сетки, её высота задаёт высоту ряда, и без этого низ
двух колонок разъезжается на длину левой.

Параллакса нет у коллажа сцены «О территории»: стенд залипает по центру экрана, а
`view()` на залипшем элементе почти не двигается — ход стоял бы на месте. Своё
движение у плашек уже есть: затухание очередью и раскрытие клипом.

**Идиома блока одна на всю страницу:** заголовок по центру, дивайдер во всю
колонку и короткие пункты в строку под ним. Так собраны подписи первого экрана и
подписи «О территории» — это не повтор, а единственная опора, по которой соседние
секции читаются одной страницей. Панели внутри блоков — бумажные и без скругления,
как карточка легенды.

Исключение ровно одно — «О конкурсе»: блок ростом в экран со своей раскладкой (см.
ниже). Оно оправдано главным CTA страницы, и заводить второе такое же нельзя: два
исключения из четырёх секций — это уже не идиома с исключением, а её отсутствие.

**Надзаголовков над `h2` нет ни в одной секции** — заказчик их снял, и возвращать
по одному нельзя: строка над заголовком в одном блоке из четырёх читается сбоем
ритма, а не акцентом. Блок начинается заголовком, отступ сверху даёт спейсер
секции — во всех четырёх секциях он одинаковый, это видно замером. Сам стиль
`u-text-style-eyebrow-*` остался в системе и работает: им набраны ярлыки внутри
блоков — единицы счётчика, подписи групп логотипов и колонок футера.
У панелей голосования состояние теперь несёт сам заголовок: «скоро появятся»,
«выберите», «берег выбрал».

**Темы:** территория `light`, конкурс `brand`, голосование `light`, «О проекте»
`light`, футер `brand`. Территория стоит первой не для ритма, а потому что финальный
наплыв сцены открывает её саму: секция поднимается снизу под маской и стоит на месте
к тому моменту, как пин отпускает. Тёмный блок стоит там, где главный CTA, — коралл
на тёмно-синем это та же пара, что у кнопки в хедере.

Чередование через одну кончается на «О проекте»: тема там светлая по просьбе
заказчика, и два светлых блока подряд (голосование и «О проекте») — следствие этого
решения. Ритм возвращает футер: он тёмный, и границу между ним и светлым блоком рисует
сам цвет, а не линия. «О проекте» обратно в `brand` не отдавать.

**Место под видео — бокс 16:9**, и это число стоит в стилях компонента, а не
приезжает манифестом: 16:9 — формат будущей съёмки, а доли кропов пайплайна к ней
отношения не имеют. Внутри до съёмки лежит заглушка — `fullbleed`-кроп 1.6:1, —
и ложится в бокс обрезкой (`object-fit: cover`), теряя примерно по 5% сверху и
снизу. Арт-дирекшна нет: `letterbox` 2.8:1 в 16:9 потерял бы треть ширины кадра.
Из манифеста читаются ширины — набор реально собранных файлов. Форма живёт в CSS,
а не в атрибутах `width`/`height`: атрибуты описывают файл внутри, а бокс обязан
стоять 16:9 и до загрузки, и после подмены заглушки.

**Кадр раскрывается прокруткой.** Клип идёт от `inset(25%)` со всех сторон до нуля
и доходит до полного ровно тогда, когда верхняя кромка кадра встаёт под верхнюю
кромку экрана; дальше кадр просто стоит открытым. Начало не из нуля намеренно:
из нуля это читалось бы появлением картинки, а нужно раскрытие уже стоящей на
месте.

Прогресс считает браузер по `view()`-таймлайну, а не rAF-подписка на скролл: ход
не отстаёт от прокрутки ни на кадр, не занимает главный поток и не заводит второго
слушателя рядом с Lenis. Диапазон назван кромками — `entry 0%` (верх кадра на
нижней кромке экрана) → `exit 0%` (верх кадра на верхней), — своих чисел у него
нет. Два условия, которые нельзя развязывать:

- **Ход лежит внутри `@supports (animation-timeline: view())`,** а базовое
  состояние — открытый кадр. Без этого браузер без таймлайна проиграл бы ту же
  анимацию по обычному времени: подрезал кадр и оставил его подрезанным насовсем.
- **Длительность не задана.** У прогрессного таймлайна она `auto`, а любое время в
  секундах ужало бы весь ход в долю диапазона.

**Подпись лежит оверлеем на кадре и уходит под ту же маску.** Она стоит в той же
ячейке сетки, что кадр (`grid-area: 1 / 1`), поэтому клип назначен всему боксу, а
не одной картинке, и подпись проступает ровно там, где кадр открылся. Разнесена по
краям: слева что это, справа статус заглушки. Набрана вывороткой
`u-text-highlights` — тот же `--fg-highlights`, что сцена читает для белых форм
кальки: подпись лежит на кадре, а не на бумаге, и текст темы на бледной панораме
теряется.

Стики считает по своей ячейке, то есть по самому кадру: пока верхняя кромка кадра
ниже середины экрана, подпись стоит по этой кромке, дальше держится середины и
отпускается на нижней кромке. Центрируется сдвигом на половину себя, а не вычетом
строки из `50svh`: строк у правой части на узком экране больше одной, и вычет
разъехался бы с её настоящей высотой; сдвиг живёт в отрисовке и на диапазон стики
не влияет. `align-self: start` обязателен — растянутая по ячейке подпись занимала
бы её целиком, и двигать стики было бы нечего. Абсолютным позиционированием то же
не собрать: стики абсолютным элементам недоступен.

### Сцена с двумя подблоками текста

`TerritoryStory.astro` — сцена длиной в три экрана на месте прежних двух текстовых
колонок блока. Стенд в один экран залипает `sticky`; композиция одна: заголовок по
центру, текст прямо под ним (блок по центру, выключка левая), вокруг шесть кадров в
хаотичном порядке. На середине пина подблок сменяется: строки первого уходят под
верхнюю кромку своих масок, строки второго приходят из-под нижних; уходящие кадры
гаснут очередью, приходящие раскрываются клипом из своего центра.

Шов между заголовком и текстом стоит по середине стенда (`grid-template-rows: 1fr
1fr`, заголовок `align-self: end`, текст `start`). Центрировать каждый подблок
целиком нельзя: строк у них разное число, и на смене вся композиция подпрыгивала бы.

**Смена идёт своим временем — единственное место на сайте, где ход не функция
прокрутки.** Прокрутка даёт одну команду: середина сцены прошла середину экрана.
Дальше `--swap` = 0.9 с на `--ease-expo`, шаг очереди `--line-step` = 0.04 с на
строку.

Команду приносит `IntersectionObserver`, и три его свойства держатся вместе:

- **Метка — вторая половина сцены, а не 1px.** Короткую метку быстрый скролл
  проскакивает между кадрами, и команда не приходит вовсе.
- **Корень сжат полями до линии по центру экрана** (`rootMargin: -50% 0 -50%`):
  метка перекрывает эту линию ровно на второй половине пина.
- **Фаза выводится из положения метки, и сравнивается оно с линией триггера**, а не
  с верхом экрана: `boundingClientRect.top <= rootBounds.top`. Уход метки за линию
  и возврат из-за неё — одно и то же событие, сторону видно только из координат. С
  верхней кромкой экрана вместо линии сцена ломается на выходе вниз: метка уже
  выше линии, но ещё ниже кромки, и подблоки уезжают обратно в первый прямо под
  уходящей сценой. Линию отдаёт сам наблюдатель, поэтому её половина живёт один
  раз — в `rootMargin`.

Своего слушателя скролла у сцены поэтому нет: рядом с Lenis он был бы вторым и на
каждый кадр.

**Ход ведут `transition`, а не `keyframes`:** команда приходит один раз, а
развернуться она обязана из любой точки — отмотка на полпути ведёт строку назад с
того места, где её застали, а не с начала.

**Задержка приходящего подблока висит на состоянии, а не на элементе.** Приходит на
обратном ходу уже первый подблок, и задержка, приписанная второму навсегда, дала бы
на отмотке ту самую кашу, от которой она поставлена. Сама она обязательна: маски у
подблоков свои и стоят почти на одной высоте, пущенные в один кадр они дают
полсекунды двойного текста. `--swap-lag` = 0.2 с — впятеро мельче хода, поэтому
смена остаётся одним движением.

**Строка — два узла:** `.line` держит `overflow`, `.line__in` уезжает. Один элемент
не может разом обрезать себя и уезжать из себя. Разбивку делает `hero/lines.ts`
измерением, он же ставит `--i`. Маске нужен припуск по вертикали (`padding-block`
0.1em с обратным `margin`): у дисплейного заголовка интерлиньяж 0.9, строчный бокс
мельче самих букв, и без припуска маска срезает ноги «Д» и «Ц». Ход строки —
`--line-travel` 110% плюс этот припуск: в долях своей высоты, поэтому одинаков на
любом кегле.

**`data-story-split` ставится до разбивки, и порядок обратный не работает.** Строки
считаются измерением, мерить их нужно в той раскладке, в которой они встанут: в
потоке подблок шире, и переносы посчитались бы по чужой ширине. Тот же атрибут —
гард: без строк у второго подблока нет ни одного элемента, которому можно
спрятаться, и два текста легли бы друг на друга. Разбивка идёт по
`document.fonts.ready` (шрифт решает, где переносы) и повторяется на ресайзе — на
той же ширине `prepare` не делает ничего, поэтому вертикальный ресайз бесплатен.

Прокрутка в сцене считает ровно одно — `--drift` = ±3.25svh, смещение композиции
вверх за пин: `view()`-таймлайн, диапазон `contain` совпадает с залипанием стенда
ровно. Только он и стоит под `@supports (animation-timeline: view())`: без таймлайна
сцена работает, просто стоит на месте.

**Кадры вокруг — рендеры легенд из пайплайна, а не фотографии территории:** их в
проекте нет ни одной. Взяты потому, что разные — один кадр в шести плашках
прочитался бы техническим швом, а не сменой кадров. `alt` пустой намеренно: описать
заглушку как берег значило бы соврать в самом доступном слое. Геометрия коллажа —
доли стенда, пропорция плашки, точка кропа — живёт числами в компоненте: это
art-direction, то же исключение, что у слота логотипа. На 900 кадры уходят вовсе:
от них по краям остаются полоски в палец, а текст важнее коллажа.

Базовое состояние — оба подблока стопкой в потоке, как две колонки до этой правки.
Так блок читается при `prefers-reduced-motion` и до разбивки строк.

### Ключевые объекты

Заголовок здесь метка над дивайдером — мелкий кегль по левому краю, — а не крупный
по центру: блок открывает список названий, а не строка над ним. Над линией шаг
вдвое меньше, чем под ней (`--space-lg` против `--space-2xl`): линия читается
кромкой блока названий, а не полосой, висящей между двумя половинами. Общая отбивка
`.territory__rule` перебита целиком, а не одним краем: в шапке блока она
несимметрична в другую сторону — там под линией стоят подписи, а не блок.

Под дивайдером три дорожки: кадр, поле, список из пяти названий. **Список занимает
ровно половину экрана**, и это `50%` от колонки страницы, а не доли: колонка
центрирована, поэтому её половина и есть середина экрана. Междурядья между
дорожками нет вовсе — гэп отодвинул бы границу списка от середины на свою половину;
отбивку от кадра держит средняя дорожка, она и есть поле.

Кадр — пять колонок из двенадцати, та же ширина, что у кадра закрывающего блока:
два разных размера кадра на одной странице читаются ошибкой вёрстки. Выражение
стоит в `grid-template-columns`, а не на самом кадре, потому что проценты в
дорожках считаются от сетки — на кадре те же 5/12 дали бы долю его собственной
дорожки. Описание встаёт по ширине кадра само: оно лежит в той же дорожке, и
второго правила для этого не нужно. Показан всегда один объект, и меняется он по
наведению на название. Отбивка от сцены выше максимальная в шкале,
`--space-10xl`: после трёх экранов пина блок обязан читаться новым, а не её
продолжением. Класс `obj`, а не `card`: `card` — карточка легенды, и одинаковые
имена в двух блоках путают при отладке, даже когда стили заскоупены.

Кадры — те же заглушки из пайплайна, что в сцене выше, и соответствие не
случайное: рендер каждой легенды сделан вокруг своего объекта (`legends[].object`
в манифесте). Пятый объект — исток Ангары, и его текст держится географии, которая
уже стоит в подписях блока: фактология территории приходит от заказчика.

**Пара «название — кадр» лежит в разметке рядом**, а по колонкам её разводит
сетка: пункт списка раскрыт `display: contents` и боксом не является. Разнесённые
по двум спискам, они разъехались бы порядком чтения — и с экранного диктора, и на
узком экране, где объект обязан собраться обратно в карточку. Здесь узкий экран —
это `display: block` на пункте и больше ничего.

Из этого следует устройство сетки. Кадры лежат в одной ячейке друг на друге и
спанят список целиком, а `grid-row: 1 / -1` требует явных строк — поэтому строк
ровно столько, сколько объектов (`--rows` приходит числом из разметки, а не
подобран), плюс одна гибкая в хвосте. Гибкая обязательна: при спане через неё
избыток высоты кадра уходит в неё, а без неё — растаскивает названия по высоте
кадра. `align-self: start` — по той же причине: растянутый по спану кадр занял бы
всю его высоту.

**Показанный объект держит класс, а не `:hover`.** Курсор ушёл с названия — кадр
остался. Чистым CSS это не выражается: `:has(:hover)` знает только «наведено
сейчас», то есть без наведения пришлось бы возвращать первый объект, и увод
курсора в сторону кадра сбрасывал бы показанный. Скрипт вешает `pointerenter` и
`focus` на сами кнопки — второго слушателя скролла рядом с Lenis тут нет вовсе.

Первый пункт помечен активным на сервере, поэтому без JS блок остаётся рабочим:
виден первый объект, а на 900 — все сразу. Названия — кнопки, и фокус ведёт кадр
наравне с курсором: иначе с клавиатуры видно ровно один объект из пяти. Описание
привязано к своей кнопке `aria-describedby` — иначе с диктора список названий и
стопка описаний читаются двумя несвязанными кусками.

Закрывающая мысль стоит на двух колонках: слева набор, справа портретный кадр.
Доли 7:5, а не поровну — на равных дисплейный заголовок ломался бы на вдвое
большее число строк. Линий у блока нет ни одной — ни сверху, ни внутри: от объектов
его отбивает пустое поле в максимальный шаг шкалы (`--space-10xl`), а дисплейный
заголовок начинает блок сам. Своей ссылки у блока тоже нет: условия открывает
кнопка «О конкурсе» ниже, и вторая кнопка на то же место читалась бы дублем.

Внутри левой колонки заголовок прижат к верхней кромке, а текст — к нижней
(`justify-content: space-between`). Высоту ряда
задаёт пропорция кадра, 2:3, и низ обеих колонок обязан сойтись: заголовок с
текстом вплотную читался бы одним куском, а не разнесённой композицией. У кадра
поэтому и пропорция, и `block-size: 100%` с обрезкой: если набор слева окажется
выше, кадр растянется вместе с рядом. Кадр — маяк, единственный рендер, не
занятый в объектах выше.

Мера текста ограничена в `ch`, и ограничение стоит на самих абзацах, а не на их
обёртке: `ch` считается по кеглю элемента, а обёртка набрана крупнее — на ней те же
72ch дали бы меру шире колонки, то есть не дали бы ничего.

На 900 колонка одна, а кадр становится 4:3 — портретный во всю ширину экрана занял
бы полтора экрана высоты.

Отбивка между абзацами `--space-2xl`, и это не вкус: набор идёт с вертикальным
trim, бокс абзаца обжат по кап-высоте, и 16 px дают тот же просвет, что между
строками внутри абзаца — два абзаца читаются одним.

### «О конкурсе» — единственный блок ростом в экран

Раскладка у него своя, и это осознанный отход от идиомы страницы: дисплейный
заголовок по центру в две строки, дивайдер во всю ширину, а под ним три дорожки —
условия слева, абзацы строго по центру блока, кнопки в строку по правому краю. Блок
несёт главный CTA и обязан читаться главным разворотом страницы, а не такой же
секцией, как соседние. Перенос заголовка стоит в разметке: две строки — композиция
блока, а `text-wrap` делит строку по-своему на каждой ширине (на 390 их три —
дисплейный кегль там ужат втрое, и это нормально).

**Ширина — вся страница за вычетом полей, `u-container` тут нет.** Потолок
`--page-max` обрезал бы дисплейный заголовок на широких экранах, а он здесь во всю
ширину и есть композиция. Поля — те же `--margin`, поэтому по краю страницы блок
стоит вровень с соседними секциями (замер на 1920: поле блока 38, кромка колонки
«О территории» 38).

**Высота — `min-block-size: 100svh`.** `svh`, а не `vh`: на мобильных `vh`
считается по свёрнутой панели браузера, и блок вылезал бы за экран на её высоту. И
минимум, а не фиксированная высота — на коротком экране содержимое растит секцию, а
не обрезается (замер: экран 1440×900 → секция 900, 900×800 → 919). Поля спейсеров
лежат внутри этой высоты, `box-sizing: border-box` глобально, поэтому блок занимает
ровно экран, а не экран плюс отбивки.

**Отбивки дивайдера общие для всего сайта** (`.rule`, см. ниже), гэпа у обёртки нет
вовсе. Содержимое поэтому лежит по верхней кромке, а остаток высоты уходит вниз:
растянуть композицию по экрану значило бы развести шапку с содержимым на разное
расстояние от линии, и на 1440 под списком остаётся воздух сверх нижнего спейсера.

**Центр держат равные боковые дорожки:** `minmax(0, 1fr) auto minmax(0, 1fr)`.
Именно `minmax(0, …)`, а не `1fr` — у `1fr` минимум равен min-content, и длинное
название условия слева или широкая кнопка справа растянули бы свою дорожку, сдвинув
центр молча и ровно на разницу. Средняя дорожка `auto`, а меру держат сами абзацы
(`max-inline-size` в `ch` на них): мера, вписанная в дорожку, считалась бы по кеглю
секции, а он крупнее абзаца, и то же число дало бы другую ширину. Замер: центр
абзаца совпадает с центром блока на 1920/1440/1200/1100/900/390 до пикселя.

Оба абзаца набраны одним стилем: два разных кегля читались бы лидом и сноской, а это
две части одной мысли. Кнопки — flex в строку с переносом, прижаты к правому краю
блока (замер: правая кромка набора совпадает с кромкой блока). Перенос — не запас:
между 1100 и ~1400 боковая дорожка кнопки в строку не держит, и они встают друг под
другом у того же края.

На 1100 три дорожки складываются в одну: от боковых остаётся по трети средней, и
центрировать абзац между двумя узкими колонками уже нечем. Порядок чтения тот же,
что в разметке, поэтому переставлять нечего; `grid-column` со средней и правой при
этом снимается — в одноколоночной сетке второй дорожки не существует, и явная
колонка увела бы блоки в неявную. На 560 кнопки уходят в столбец во всю ширину.

**Незаполненные значения показаны, а не выдуманы.** У «О конкурсе» четыре условия,
и два из них — сроки приёма и число финалистов — приходят из положения о конкурсе.
Они стоят как «уточняется» и набраны тише подписи (`--muted-secondary`, без веса),
тогда как настоящие значения идут основным цветом полужирным: вес читается
утверждением, и подставленное «до 15 сентября» пережило бы вёрстку и уехало в
продакшн. То же решение, что в фактологии карточки `factory`.

Сами условия набраны стилем абзаца, а не надзаголовком с уровнем: подпись
приглушённая, значение основным цветом. Разный кегль читался бы вторым уровнем
текста, а это одна плоскость с абзацем в центре — просто короткими парами.

#### Ландшафтный паттерн на фоне

`site/src/lib/topo.ts` — изолинии одного поля высот с тремя вершинами, каждый
уровень уезжает вверх со своей задержкой. Канвас, а не картинка и не SVG: линии
двигаются друг относительно друга, то есть форма пересчитывается каждый кадр, а
картинка нарушила бы ещё и правило «ассеты пишет стадия, а не рука».

Поле, а не кольца вокруг центров, — главное решение. Нижние уровни обязаны
перетекать друг в друга: у карты общий фундамент охватывает все вершины сразу.
Кольцами это не выражается вовсе — три семейства пересекались бы, и слияние
приходилось бы подделывать заливкой, то есть скрывать линии, а не сливать их. У
суммы трёх вершин низкая изолиния — одна общая кривая, высокая — три отдельных.

Профиль вершины — конус. Изолинии выходят равномерными по радиусу (у гаусса и
обратного квадрата они сбивались в пучки на склоне и в клубок у вершины — это было
видно на прогонах), а за подошвой поле ровно нулевое, поэтому фундамент чист без
всяких порогов. Радиусы заведомо перекрываются — этим горы и перетекают друг в
друга; разведи вершины дальше суммы радиусов, и останутся три отдельных массива.
Нижний уровень не нулевой: линиями рисуются только склоны. Форму гнут гармоники по
углу, которыми делится расстояние, — они гнут само поле, поэтому уровни гнутся
согласованно и от искажения не пересекаются; веса нормированы суммой, иначе
добавленная пятая гармоника молча меняла бы амплитуду всех вершин.

Три условия реализации, каждое из которых уже ломало рисунок или кадр:

- **Запас у сетки поля — вниз.** Уровень рисуется сдвинутым вверх, значит нижней
  кромке экрана соответствует строка поля ниже неё. Запас вверх оставлял внизу
  блока полосу без линий во всю ширину (замер: чернил на строку в последних 12
  строках 53–77 против 51–70 в верхней полосе — теперь кромки равноценны).
- **Радиусы считаются от полусуммы сторон**, а не от меньшей: на узком высоком
  канвасе меньшая сторона — ширина, конусы сжимались вместе с ней, и линий на
  экране почти не оставалось.
- **Поле считается один раз на размер.** Сдвиг уровня — чистый перенос по
  вертикали, поэтому марш идёт по той же сетке, а сдвиг прибавляется к экранным
  координатам: ни пересчёта поля, ни интерполяции строк. Кадр при прокрутке — 8 мс
  на 1440×900 вместе со самой прокруткой, кадр без изменения прогресса не
  перерисовывается вовсе.

Ход — 13% высоты канваса, разброс по времени 40% хода: все уровни проходят один
путь, но трогаются в разное время (внутренний первым, фундамент последним), поэтому
линии расходятся к середине прокрутки и сходятся к концу. Разные скорости вместо
задержки пробовали — внутренний уровень уезжает от своего поля навсегда и к концу
блока превращает стопку в кашу, которая обратно не собирается. Замер хода:
−116 px от входа до выхода секции.

При `prefers-reduced-motion` паттерн рисуется один раз в середине хода: крайнее
положение читалось бы недоехавшим, а середина — законченным рисунком.

Обе кнопки блока ведут на страницы, которых ещё нет (`/competition`, `/apply`) —
тот же статус, что у «Подробнее» в карточке легенды. Ссылка «О конкурсе» с первого
экрана и кнопка заявки в хедере переведены на них же: висячий якорь `#apply`
не вёл никуда.

### Три состояния голосования

Все три свёрстаны и лежат в DOM одновременно, показана одна панель — `hidden`.
Чем состояние переключается в продакшне (дата, флаг в контенте, админка), ещё не
решено, поэтому остался **временный переключатель** — но убран под иконку-шестерёнку:
она стоит абсолютом у самой кромки блока (8 px, `--space-2xs`) по центру по вертикали,
а три кнопки лежат в поп-апе рядом. Шестерёнка нарисована ободом с толстыми зубьями:
тонкие лучи читались солнцем, то есть переключателем темы. Строкой над блоком он читался частью вёрстки, а
служебному элементу в композиции места быть не должно вовсе. Иконка приглушена и
проявляется под курсором, отбивка у обоих пунктирная — как у пустых слотов
логотипов, то есть читается временной. Поп-ап закрывается по Escape и по клику вне:
оставленный открытым, он перекрывает содержимое. На 900 иконка уходит в поток над
блоком — у кромки узкого экрана она налезает на текст.

Выбор уезжает в адрес (`?voting=during`) через `history.replaceState`: ссылкой на
конкретный вариант можно поделиться с заказчиком, не собирая сборку под каждый, и
перезагрузка выбор не сбрасывает. Разбор параметра уйдёт вместе с переключателем.

Без JS ни иконки, ни поп-апа нет — скрыто атрибутом из разметки, а не стилями:
кнопки, которые ничего не делают, хуже, чем их отсутствие. Видна панель `during` —
она же `DEFAULT_STATE` и первый кадр с JS: это состояние с отсчётом до закрытия,
коллажем и кнопкой на проекты, по нему и идёт приёмка. Появится механизм назначения
состояния — `DEFAULT_STATE` уйдёт вместе с переключателем.

#### Порядок в панели и отсчёт

Заголовок, дивайдер, отсчёт во всю ширину и под ним пояснение — колонкой строго по
центру блока (замер: центр абзаца совпадает с центром блока на 1920/1440/900/390, мера
624 px = 64ch на 1440). Центрирует каждый абзац сам автополями: обёртке это не поручить —
её дорожка сайзится по max-content абзаца, то есть по всей ширине блока, и
`justify-content: center` не давал ничего, колонка стояла по левому краю.

Набор по формату, и это следствие центрирования, а не отдельное решение: при рваном
правом крае масса текста стоит левее центра бокса — замер давал 711 при центре 720, а
последняя строка кончалась за 470 px до правой кромки, и абзац читался сдвинутым. По
формату краска занимает бокс целиком, центры совпадают, последняя строка остаётся по
левому краю сама. `text-wrap: balance` тут не годится вовсе: он ровняет длины строк, но
бокс остаётся своей ширины, и масса уезжает влево ещё сильнее — замер дал центр 660.
Тот же приём у абзацев «О конкурсе»: там краска стояла на 21–32 px левее центра дорожки.

С этого началось, а закончилось общим правилом: по формату набраны все контентные
абзацы страницы — голосование, «О конкурсе», сцена «О территории» и её закрывающая
мысль, карточка легенды, «О проекте». Замер по краю строки (ink через `Range`): у всех
строк, кроме последней в абзаце, хвост до правой кромки нулевой. В сцене «О территории»
выключку при этом держит `text-align-last: justify` у самих строк, а не `text-align` у
абзаца: строки там разложены по своим блокам, и в каждом строка единственная, то есть
последняя, — а последнюю `justify` не растягивает. Правило поставлено всем строкам,
кроме последней в абзаце, и переносы от него не меняются: разбивка меряет их до
выключки, а `justify` правит только пробелы внутри уже сложенной строки.

Заголовок уровня h5 и в две строки переносом в разметке:
главный объект блока — отсчёт, и крупный заголовок спорил бы с ним за внимание, а у
мелкого кегля строка сама не переносится. Отбивки дивайдера общие для всего сайта
(замер: 24 сверху, 12 снизу). Служебной строки под отсчётом больше нет — заказчик её
снял; условные даты остались только в коде.

Отсчёт стоит в двух состояниях: до старта считает по `STARTS_AT`, во время
голосования — по `ENDS_AT`. Формат — ISO со смещением (`2026-09-25T12:00:00+08:00`,
Иркутск): без смещения браузер посетителя прочитает дату в своём часовом поясе и
покажет чужой отсчёт. Обновляется раз в минуту — младший разряд минуты, чаще считать
нечего. Цифры табличные, все разряды с ведущим нулём: иначе смена разряда дёргает
ширину строки. Пустая строка вместо даты по-прежнему работает — отсчёт встаёт с
прочерками и просит дату.

**ВРЕМЕННО: даты условные**, чтобы отсчёт было видно живым. Настоящие приходят из
положения о конкурсе — поставить их на место условных, других правок не нужно.

Кегль считается от ширины блока в `cqw`, а не в `vw`: за потолком колонки
(`--page-max`) отсчёт перестаёт расти вместе с ней, на `vw` продолжал бы и вылез бы
за колонку. И считается он от числа знаков — `--chars` ставит скрипт по тому, что
реально написал: у отсчёта дальше 99 дней разрядов семь, и фиксированный кегль вылез
бы за дорожку. Делитель замерен: табличная цифра занимает 0.6 кегля плюс 0.01 на
мелкие двоеточия с их полями. Замер на 1440: кегль 376 px, цифры 436 px из 445
дорожки — по 4 px воздуха до разделителя.

**Трекинг возвращается полем в конце числа, иначе краска стоит не по центру.** Трекинг
сидит после каждого знака, включая последний, поэтому бокс числа короче своей краски с
правого края: центрируя бокс, браузер ставил краску правее центра дорожки ровно на
половину трекинга — 20 px на 1440, и «часы» читались сдвинутыми. Поле в конце числа
возвращает эту долю, и центр краски совпадает с центром дорожки (замер: 721 против 720
на 1440, 195 против 195 на 390). У последнего числа поле снимается обратно отрицательным
полем — оно прижато к правой кромке, и без этого краска кончалась бы на полтрекинга
раньше. Трекинг живёт одним числом `--tracking`: два места, где он участвует,
разъезжаться не должны.

Трекинг у чисел плотный — минус 0.11em, и это не на глаз: ширина табличного знака
0.62em, самая широкая краска (ноль) 0.49em, то есть пазух около 0.13em на знак. Замер
на 1440: между краской соседних цифр 9 px. Дальше подбирать нельзя, первыми слипнутся
широкие 0 и 8.

**Плотный трекинг требует припуска у окна знака, иначе цифру срезает.** Трекинг сидит
в конце знака, поэтому ячейка становится уже самой краски, а `overflow: clip` режет по
её кромке: правый край цифры уходил под обрез ровно на разницу (замер: 10 px). Лечится
припуском справа с обратным полем — окно шире краски, а бокс остаётся прежней ширины,
поэтому соседние знаки не разъезжаются. Только справа: слева пазуха знака нетронута, а
припуск слева уводил бы первое число за кромку блока. Замер после правки: краска
кончается на 13 px внутри окна, зазор между цифрами 9 px, переполнения документа нет.

Кромки блока при этом держат боксы, а не краска: у цифры остаётся своя пазуха, поэтому
краска первого числа начинается на 26 px внутри кромки, а последнего кончается за 13 px
до неё. Оптический сдвиг под кромку не делаю намеренно — у табличных цифр пазухи
разные, и «1» на месте «0» уехала бы от края заметнее, чем стоит сейчас.

От плотного трекинга каждое число стало уже своей дорожки, поэтому крайние прижаты к
кромкам блока, а среднее стоит по центру дорожки (замер: левый край первого числа 32 =
кромка блока, правый край последнего 1408 = её же). Отсчёт читается от кромки до
кромки, а слак ушёл к двоеточиям.

Дорожек пять: три равные под числа и две по контенту под двоеточия. Равные дорожки —
это и есть фиксированное положение разделителей: они стоят на границах третей
(замер: центры 487 и 953 при блоке 1376) и не ездят вслед за шириной цифр. Сами
двоеточия своим кеглем, мелким (`--h-sm`): на кегле чисел разделитель занимал бы
место третьего разряда. Цвет у них основной, а не приглушённый: при таком кегле
приглушённый знак между тремя огромными числами теряется. По вертикали они по центру
числа — на базовой линии мелкий знак
под трёхсотпиксельной цифрой читается провалившимся.

**Подписи «дни / часы / минуты» стоят над числами.** Подпись читается раньше числа —
«дни», потом «66», — и низ отсчёта остаётся свободным под боковые кадры коллажа: они
заходят на цифры снизу, и под ними подписи пропадали целиком, видна оставалась одна
«часы». Строка задана явно и подписям, и числам с двоеточиями: автоматическое
размещение расставило бы подписи над числом, над двоеточием и над следующим числом, а
числа ушли бы в свободные ячейки той же строки. Дорожка у каждой подписи своя, явная
(замер: центры совпадают с центрами чисел до пикселя).

Набор подписей — строчные основным цветом (`text-sm`, `--fg`, замер 12 px), а не
капитель надзаголовка приглушённым: так решил заказчик. Тем же стилем набрана строка
под отсчётом — она стоит по центру блока, а не по центру среднего разряда, потому что
относится ко всему отсчёту, и текст у неё свой в каждом состоянии: «до старта
голосования» в `before`, «до конца голосования» в `during`. Одна строка на оба
состояния оказалась бы неправдой в одном из них.

**Вход отсчёта — набор по скролл-триггеру.** У каждого знака своя лента из цифр с
целевой в конце (2.1 с ход, задержка 0.07 с на знак от старта, шесть случайных цифр
перед целевой), и лента уезжает по Y в своей маске. Три числа связаны: лента проходит
свои знаки за время хода, то есть скорость набора — их отношение. На восьми знаках за
0.9 с цифры сливались в полосу, читать в ней было нечего.

Задержка мелкая относительно хода: следующая цифра трогается почти сразу за
предыдущей, и набор читается одним движением с оттяжкой, а не шестью отдельными
событиями — так было на 0.17 с.

**Шаг ленты — в `em`, а не в процентах, и это уже ломало блок целиком.** Процент у
`translateY` считается от высоты самой ленты, а она длиной в несколько знаков:
`-800%` уводило её на 25 402 px вместо 3 008, в окне знака оставалась пустота, и
отсчёта не было видно вовсе — цифры мелькали и исчезали. Знак ростом ровно в `1em`,
поэтому `em` тут и есть номер знака. Замер после правки: высота окна знака 376 px,
высота элемента ленты 376 px, конечное смещение −2 256 px = 6 × 376, а видимая в
окне цифра совпадает с целевой у всех шести знаков. Едет позиция ленты, а не
подменяется текст в кадре: подмена шагами читалась мерцанием, а один `transform` с
задержкой считает компоузитор — своих кадров у набора нет вовсе. Замер: на 30-м
кадре первая лента уже на −1 767 px, четвёртая только тронулась, шестая ещё на нуле —
задержка идёт от старта, как и задумано.

Команду («отсчёт впервые вошёл в кадр») приносит `IntersectionObserver` с порогом в
четверть высоты — метку в пиксель быстрый скролл проскакивает между кадрами, — и на
этом наблюдатель снимается. Своего слушателя скролла нет: рядом с Lenis он был бы
вторым и на каждый кадр.

**Между отмоткой и отпусканием стоит принудительный пересчёт, и снимать его нельзя.**
Набор — два присваивания подряд: сначала лента возвращается к началу без перехода,
потом отпускается к целевой цифре. Без чтения геометрии (`void el.offsetHeight`)
браузер склеивает их в одно, начальным состоянием перехода остаётся целевая цифра, и
движения нет вовсе — молча, без единой ошибки. Кадр (`requestAnimationFrame`) на это
не годится: он рассчитывает, что между двумя записями будет отрисовка, а наблюдатель
отдаёт первую запись не внутри кадра. Замер на одной ленте за проход: с кадром одно
положение (`transition-duration` уже 2.1 с, а смещение всё время конечное), с
пересчётом — 33 промежуточных.

**Играет набор один раз за загрузку.** Отсчёт — показание, а не событие: пересобирать
его при каждом проходе мимо блока значит объявлять изменение, которого не было. Замер:
на первом проходе ленты дают 389 разных положений, на втором — шесть, то есть стоят, и
цифры остаются на своих местах. Смена минуты набор тоже не проигрывает. Переключение
состояния проигрывает, но только у той панели, которая ещё не набиралась: скрытая
панель на observer не отзывается вовсе и открылась бы с уже стоящими цифрами (замер:
`during` при первом показе даёт 421 положение). Лента стоит на целевой цифре и без скрипта, поэтому при
`prefers-reduced-motion` отсчёт просто виден числом.

Знаку нужно два узла: `.timer__ch` держит маску (`overflow: clip`, высота ровно в
одну цифру — по ней же считается шаг ленты), `.timer__reel` уезжает. Один элемент не
может разом обрезать себя и уезжать из себя — то же, что у строк сцены
«О территории».

**Стили этих узлов обязаны быть в `:global`, и это общее правило, а не мелочь.**
Ячейки и ленту создаёт скрипт, а скоуп Astro метит только узлы шаблона: без
`:global` правило `.timer__reel { display: block }` до ленты не доходило вовсе —
спаны оставались `display: inline`, а к инлайну `transform` не применяется, и лента
стояла на месте молча, без единой ошибки в консоли (в замере: инлайновый
`translateY(-800%)` при вычисленном `matrix(1, 0, 0, 1, 0, 0)`). Пишется как
`.timer__num :global(.timer__reel)` — снаружи узел шаблона, поэтому скоуп не потерян.

Сама сетка отсчёта скрыта от скринридера, а значение ему читает отдельная строка
(«Осталось: 03 дн. 05 ч. 06 мин.»): вслух «03 : 05 : 06» не значит ничего.

#### Коллаж вокруг отсчёта

В панели `during` вокруг набора стоят три кадра: два портретных по бокам от текста и
широкий под ним, а под широким — кнопка на проекты. Держит их одна сетка с теми же
дорожками, что у «О конкурсе» — `minmax(0, 1fr) auto minmax(0, 1fr)`, меру средней
держат сами абзацы. Набор лежит во всех трёх дорожках, боковые кадры — в крайних и в
тех же строках: этим они его и перекрывают, абсолютов здесь нет вовсе, а место кадра
это остаток от меры текста. Порядок наложения задан явно (`isolation` на сетке,
`z-index` у кадров): ленты набора создаёт скрипт, в потоке они идут позже и по
умолчанию легли бы поверх кадров.

Кадр не шире 18rem — 288 px против дорожки числа в 444 px на 1440. На 20rem он
накрывал первый разряд «дней» целиком, а перекрытие обязано читаться наложением, а не
заслонкой.

**Кадры стоят в строке текста, а не набора.** Кромка их дорожки совпадает с нижней
кромкой отсчёта на любой ширине, поэтому перекрытие остаётся тем же и на 1920: в строке
набора цифры уходили под кадры целиком — отсчёт растёт вместе с блоком (кегль в `cqw`),
а кадр шириной 18rem не растёт. Отбивка текста от отсчёта при этом лежит внутри строки,
на самом абзаце (`--space-6xl`), а не гэпом сетки — иначе кромка дорожки уехала бы ниже.

**Едет сама обёртка, а не картинка внутри неё.** Внутренний параллакс `.photo` у боковых
кадров снят (`animation: none`, `scale: 1`): обёртка идёт вверх, картинка в ней вниз —
два хода в одном месте гасят друг друга, и на глаз стоит либо то, либо другое. Ход 9svh
в обе стороны от `--y`: замер даёт 162 px пути на экране 900, 194 на 1080 и 234 на 1300.
Направления встречные — одна анимация с `animation-direction: reverse` у правого кадра;
второй набор кейфреймов разъехался бы с первым на первой же правке амплитуды. Прогресс
считает браузер по `view()`-таймлайну, диапазон `cover`; без таймлайна кадры просто стоят
на своих местах.

**Смещения у двух кадров закреплены по-разному, и это не небрежность — у них разные
условия.** У левого закреплена середина пути (`--y` числом): требование мягкое, он
должен немного заходить на цифры, и замер на 1440 даёт перекрытие от нуля до 40 px, пока
отсчёт стоит в кадре (на экране 1300 — 14–65 px); к выходу блока оно доходит до 113 px,
но там отсчёта уже не видно. У правого закреплена верхняя точка: в `--y` прибавлен сам
ход, поэтому `--y − --drift` от амплитуды не зависит вовсе и всегда равен 8% его высоты
ниже кромки отсчёта. Требование там жёсткое — не коснуться отсчёта ни в одной точке, — а
ход задан в `svh` и на высоком экране растёт: с закреплённой серединой замер давал зазор
5 px на 900 и −31 px на 1300, то есть кадр уезжал под цифры; с закреплённой верхней
точкой зазор 35 px на всех трёх высотах.

Широкий кадр стоит в средней дорожке, и этим он равен тексту по ширине на любом
экране — замер: 624/624 на 1440, 594/594 на 1024, 571/571 на 700, 390/390 на 480,
переполнения по горизонтали нигде нет. Поэтому на узком экране сетка не складывается в
одну колонку: уходят только боковые кадры (`display: none` на 1100 — от них там
остаётся по полоске в палец), а пустые дорожки схлопываются сами, у них
`minmax(0, 1fr)`. Сложи её в одну колонку — широкий кадр растянулся бы во всю страницу
и перестал бы совпадать с набором.

Кнопка под кадром стоит по центру: композиция панели центрированная, и по левому краю
под симметричным кадром она читалась бы сбитой. В панели «завершено» кадра нет, и там
ряд остаётся по левому краю — единственному объекту блока центровка не нужна.

ВРЕМЕННО кадры — фотографии-заглушки (`lib/photos.ts`, ключи `VOTE_PHOTOS`): боковые
взяты разными по тону намеренно, светлый туман против тёмной воды, — на одинаковых
пара по краям одного набора читалась бы двумя половинами одной плашки. Ветка с
рендерами пайплайна стоит рядом и работает (`PHOTOS = false`), ширины для неё
приходят манифестом. `alt` пустой: описать заглушку как берег значило бы соврать в
самом доступном слое.

### Логотипы, которых ещё нет

Блок собран описью, а не плашками. Шапка: дисплейный заголовок в две строки по центру
(перенос в разметке), под ним дивайдер, дальше две равные колонки — справа оба абзаца
друг под другом одним цветом, слева в оставшемся месте портретный кадр в треть колонки
(замер: 223 px при половине колонки 676). Абзацы не разведены ни цветом, ни кеглем:
это две части одной мысли — что за проект и почему решение общее, — и приглушённый
второй читался бы сноской. Мера — в `ch` на самих абзацах, а не на обёртке: `ch`
считается по кеглю элемента, и абзац получается уже своей колонки. Дорожки
`minmax(0, 1fr)`, а не `1fr`: у `1fr` минимум равен min-content, и длинное слово
сделало бы половины разными на глаз.

Доля кадра стоит процентом, а не в rem: «треть колонки» и есть требование, а колонка
меняется вместе с шириной страницы. Бокс — тот же `.photo`, что у остальных кадров
страницы, поэтому картинка внутри идёт параллаксом и лежит абсолютом, а форму держит
пропорция на боксе. На 900 колонок нет, и доля крупнее (45%): треть узкой колонки
читается уже не кадром, а иконкой.

Линии групп на ступень тише основной, и ступень выбрана замером: на `--muted` (0.64)
линия в один пиксель от `--border` на глаз не отличается вовсе, поэтому стоит
`--muted-secondary` (0.4). Приглушение, заметное в тексте, в линии не читается — это
общее наблюдение, а не особенность блока.

Ниже четыре строки групп — организаторы, партнёры, экспертные организации,
государственные структуры. В строке дивайдер во всю колонку, слева название с
описанием роли, справа логотипы; дорожки те же, что у шапки. Дивайдер стоит в самой
строке, поэтому своей линии под шапкой блока нет — первая линия группы её и отбивает,
а отбивки у линии общие для всего сайта, так что гэпа над содержимым строки нет вовсе.
Междурядье между группами крупное (`--space-5xl`): иначе линия следующей группы
читается частью предыдущей, а не началом новой. На 900 обе пары дорожек складываются в
одну — половина колонки уже меры абзаца.

Файлов нет ни одного: логотипы это чужие товарные знаки, их нельзя ни нарисовать, ни
подставить похожими. Поэтому у каждой группы в конфиге компонента лежит `items: []` и
число ожидаемых слотов. Пришёл файл — он ложится в `items`, и слот сам становится
`<img>`; пока не пришёл, на его месте рамка пунктиром с подписью «логотип». Пунктир
здесь важен: он читается ожидающим местом, а не элементом дизайна, и его не спутать
при приёмке.

Описание группы (`note`) — роль, а не факт: ни имён, ни чисел, ни сроков. Всё это
приходит от заказчика вместе с логотипами, и подставленное «двенадцать партнёров»
пережило бы вёрстку. Формулировки ролей наши и меняются одной строкой в конфиге.

Геометрия слота (`9rem`, пропорция 12/5) — размер элемента, а не отступ из шкалы,
поэтому число живёт в компоненте, как `3.5rem` у мишени светлячка. Вертикальные
знаки лягут по высоте и останутся уже слота — это нормально, `object-fit: contain`.

### Футер

Футер ростом в экран (`min-block-size: 100svh`) и в тёмной теме — по просьбе заказчика.
Две части, и разводит их пустое место, а не линия: сверху подпись проекта с навигацией,
снизу, по кромке экрана, — крупный леттеринг, а над ним выходные данные (копирайт слева,
разработка справа). Колонки страницы у футера нет вовсе — обе части идут во всю ширину
экрана за вычетом полей сайта (те же `--margin`, но без потолка `--page-max`), поэтому
их кромки совпадают на любой ширине: замер на 2400 даёт 38 и 2362 у всех трёх строк —
леттеринга, выходных данных и навигации. С колонкой верх на широком экране стоял бы по
центру, а леттеринг — от края до края. Сетка футера — две строки,
`1fr auto`: верхняя тянется, нижняя встаёт по своей высоте, поэтому леттеринг всегда
стоит у нижней кромки при любой высоте экрана.

Капители в подписях нет ни в одной — ни у названий колонок, ни у маленького леттеринга
в шапке: заказчик её снял, и `u-transform-none` стоит поверх стиля заголовка, а сам стиль
не тронут. У крупного леттеринга капитель, наоборот, оставлена — это набор, а не подпись.

**Кегль леттеринга считается от ширины полосы, а не задан числом.** `100cqw / 8.66`, где
делитель — ширина строки в кеглях, замеренная под эту строку, гарнитуру, вес и капитель.
И кегль, и ширина строки линейны по `cqw`, поэтому краска занимает полосу целиком на
любой ширине: замер 1845/1845 на 1920, 1376/1376 на 1440, 970/970 на 1024, 656/656 на 700,
449/449 на 480, переполнения по горизонтали нет нигде. Поменяешь строку, трекинг, вес или
капитель — пересчитывай делитель.

Междурядье ссылок в колонках — `calc(var(--space-2xs) / 1.5)`, в полтора раза меньше
прежнего шага (замер: 5.33 px против 8). Множитель от того же шага шкалы, а не новое
число: «в полтора раза» остаётся собой и после правки шкалы.

**Содержимое футера выезжает сверху за прокруткой.** Ход ведёт `view()`-таймлайн на
обёртке содержимого, диапазон `entry 0% → entry 100%`: смещение идёт от −12svh к нулю и
кончается тогда, когда футер дошёл до низа — дальше и прокрутке идти некуда. Замер
колесом (страница на Lenis, `scrollTo` рядом с пином даёт скачки): −108 px на входе,
−20 px за 227 px до конца, ноль на последних 92 px и до самого низа. Обёртка одна на обе
части: две с одним ходом разъехались бы на первой же правке амплитуды. Футер при этом
`overflow: clip` — сдвинутое вверх содержимое обязано быть обрезано его кромкой, а не
висеть над блоком выше. Без поддержки таймлайна и при `prefers-reduced-motion`
содержимое просто стоит на месте.

Ссылки на положение, политику и юридическую информацию ведут на `/competition/rules`,
`/privacy`, `/legal` — страниц нет, тот же статус, что у «Подробнее». Навигация по
странице написана абсолютными адресами (`/#territory`), чтобы футер работал и с
внутренних страниц: переезд в `Base.astro` будет одной строкой, когда они появятся.

Контактов и соцсетей у нас нет, и адрес из головы хуже пустого места — письмо по
нему уйдёт в никуда. Там стоит «уточняется», та же договорённость, что у фактов
конкурса и даты голосования. Год в копирайте берётся на сборке: статика
пересобирается при каждой правке контента, а вписанное число разъедется с ней молча.

Дисклеймера о достоверности материалов в футере больше нет — заказчик его снял. Если
он вернётся, место ему в нижней части, рядом с выходными данными: легенды на сайте
художественный текст, и рядом с фактами о территории это стоит говорить прямо.
